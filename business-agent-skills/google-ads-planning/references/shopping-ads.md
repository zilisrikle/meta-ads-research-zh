# Google 购物广告

## 操作实践

购物广告的表现主要取决于产品 Feed、价格、产品与市场的匹配度、落地页的购买阻力，以及考虑利润的出价。系列设置也重要，但 Feed 是定向层和创意层。

### 最重要的事项

- **产品标题通常是第一个 Feed 杠杆。** 把买家会搜索的词前置：品类、关键属性、品牌/型号，以及相关的尺寸/颜色/材质。只有当品牌是搜索意图时才品牌前置。
- **Feed 健康不只是拒登。** 隐性的 GTIN 错误、过期的价格/库存、弱 product_type、差图片或落地页不匹配，都可能在没有明显账户告警的情况下压制展示。
- **自定义标签应服务于决策。** 当它们能驱动预算、出价或 P-MAX 列表组选择时，利润层级、库存/备货状态、爆款/长尾、季节性、促销状态都很有用。
- **利润比收入 ROAS 更重要。** 只看收入的 tROAS 会在低毛利产品上过度投入。条件允许时，传入考虑利润的价值，或按利润拆分。
- **补充 Feed 是快速运营工具。** 用它快速测试标题修复、自定义标签和 product_type 变更，验证有效的模式再推到上游。
- **标准购物仍有其位置。** 可用于诊断、长尾 SKU 保护、库存多/素材少的目录，或 P-MAX 隐藏太多信息的情况。
- **免费商品展示值得维护，但不要围绕它做预测。** 把它当增量曝光和再营销池的输入，而不是核心增长引擎。

- **标题结构应跟随买家搜索行为。** 泛品类搜索，品类和关键属性前置；品牌主导或型号主导的品类，品牌/型号前置。用搜索字词验证，而不是套用一个万能公式。
- **自定义标签应映射到业务杠杆。** 利润层级通常最有用；当库存状态、动销速度、爆款/长尾、促销、季节性能改变出价或系列纳入时，它们也很有用。
- **补充 Feed 是最快的测试层。** 用它做标题改写、标签、product_type 修正和临时陈列修复。把稳定的胜出者推回主 Feed，避免长期漂移。
- **长尾产品可能需要隔离。** P-MAX 和智能出价常常集中在高信号的胜出者上。如果长尾 SKU 本该卖得动却从没有展示，用更宽松的目标或独立结构隔离它们。
- **促销和价格标注是真正的创意杠杆。** 特价、促销、运费、退货政策和评价，可以在不动系列设置的情况下改变 CTR/CVR。
- **库存感知出价可以很简单。** 低/正常/高库存或备货天数等标签，可以防止在即将断货的 SKU 上浪费花费，并优先能实际履约的产品。
- **不要轻易动产品 ID。** 稳定的 ID 保留历史和产品连续性。改变 ID 的 Feed 重建会造成本可避免的学习损失。

### 诊断

| 症状 | 先查什么 | 可能的动作 |
|---|---|---|
| 展示低 | 拒登、GTIN/品类/标题质量、预算/目标 | 修 Feed、改进标题、放宽目标、扩大符合条件的产品 |
| 点击率低 | 标题相关性、图片、价格竞争力、促销/评价 | 改写标题、改进图片、加促销、检查定价 |
| 转化率低 | 落地页、运费/退货、价格一致性、结账阻力 | 修落地页、信任信号、运费清晰度、结账流程 |
| ROAS 低 | 利润组合、产品胜负分布、价值、库存 | 按利润拆分、隔离爆款/长尾、用考虑利润的价值 |
| 长尾从不展示 | 产品分组、P-MAX 偏向胜出者 | 有需求时用宽松目标隔离长尾 SKU |

### 常见陷阱

- 试图用改系列设置解决 Feed 或定价问题。
- 对利润差异很大的产品用同一个 ROAS 目标。
- Feed 重建时破坏产品 ID，丢失连续性。
- 忽略商家中心诊断和按 SKU 的展示率。

## 1. 商家中心设置

### 1-1. 初始设置检查清单

| # | 项目 | 说明 |
|---|---|---|
| 1 | 创建账户 | 在 merchants.google.com 创建，关联一个 Google 账户 |
| 2 | 商家信息 | 准确填写公司名称、地址和电话 |
| 3 | 网站注册 | 注册网站网址并验证所有权（HTML 标签、Google Analytics、Google Tag Manager 等） |
| 4 | 运费设置 | 配置配送方式、费用和时效。与 Feed 的 `shipping` 属性保持一致 |
| 5 | 退货政策 | 退货条款和退货网址（越来越多国家要求必填） |
| 6 | Google Ads 关联 | 关联到 Google Ads 账户 |
| 7 | 计划加入 | 启用"购物广告"和"免费商品展示" |

### 1-2. 商家中心能力检查

商家中心的功能和界面标签经常变化。做规划时，只验证影响 Feed 质量、展示资格或陈列的能力：

| 能力 | 规划相关性 |
|---|---|
| 产品诊断和商品自动更新 | 防止因价格、库存、图片或落地页不匹配造成的隐性损失 |
| 促销、产品评分、运费和退货标注 | 不改系列也能提高 CTR/CVR |
| 补充 Feed 和程序化 Feed 管理 | 标题、自定义标签或库存数据需要频繁更新时有用 |
| 线上 / 本地变体的产品 ID 政策 | 线上和门店价格、库存或备货不同时重要 |

## 2. 产品 Feed：设计与优化

产品 Feed 是**购物广告质量的基础。** Feed 质量直接影响 CTR、CVR 和 CPC。

### 2-1. 必填属性

每个产品都必须设置的属性。

| 属性 | 说明 | 备注 |
|---|---|---|
| `id` | 产品唯一标识 | 用 SKU；不可变 |
| `title` | 产品标题 | 最多 150 字符。详情见第 3 节 |
| `description` | 产品描述 | 最多 5,000 字符。涵盖特性、材质和使用场景 |
| `link` | 产品详情页网址 | 必须与落地页完全一致 |
| `image_link` | 主产品图片网址 | 详情见第 4 节 |
| `availability` | 库存状态 | `in_stock` / `out_of_stock` / `preorder` / `backorder` 四选一 |
| `price` | 价格 | 带货币代码（例如 `99.99 USD`）。必须与落地页价格完全一致 |

### 2-2. 条件必填属性

按品类或情况必填。

| 属性 | 何时必填 | 说明 |
|---|---|---|
| `brand` | 新产品 | 品牌名（对已注册 GTIN 的产品尤其重要） |
| `gtin` | 制造商分配了 GTIN 时 | UPC / EAN / JAN。匹配和展示资格的重要依据 |
| `mpn` | 制造商未分配 GTIN 时 | 制造商零件编号 |
| `condition` | 翻新 / 二手产品必填；新产品选填 | `new` / `refurbished` / `used` |
| `google_product_category` | 建议所有产品填写 | Google 的产品品类分类体系 |
| `product_type` | 建议填写 | 你自己的产品分类体系 |
| `age_group` | 服装 | `newborn` / `infant` / `toddler` / `kids` / `adult` |
| `color` | 服装 | 产品颜色 |
| `gender` | 服装 | `male` / `female` / `unisex` |
| `size` | 服装 | 尺码 |
| `item_group_id` | 变体产品 | 颜色 / 尺码变体的分组 ID |
| `shipping` | 运费信息 | 可通过 GMC 设置批量配置 |

### 2-3. 自定义标签（custom_label_0–4）

最多 5 个自定义标签。**系列结构、出价和预算分配最重要的工具。**

| 标签 | 用例 | 示例值 |
|---|---|---|
| `custom_label_0` | 利润 | `high_margin` / `mid_margin` / `low_margin` |
| `custom_label_1` | 季节性 | `spring` / `summer` / `autumn` / `winter` / `evergreen` |
| `custom_label_2` | 销售表现 | `bestseller` / `new_arrival` / `clearance` |
| `custom_label_3` | 价格带 | `under_30` / `30_to_100` / `over_100` |
| `custom_label_4` | 促销 | `sale` / `bundle` / `regular` |

**为什么重要：**
- 利润标签实现**考虑利润的出价控制**（反映实际毛利，而不只是 ROAS）。
- 季节性标签让你在旺季前自动加码预算、旺季后回撤。
- 销售表现标签把预算集中到爆款。

### 2-4. 描述最佳实践

| 规则 | 说明 |
|---|---|
| 前 160–500 字符放重要信息 | 应对截断展示。品牌、产品类型和关键特性前置 |
| 与落地页措辞一致 | Feed 和落地页不要用不同措辞 |
| 特性和利益一起写 | 材质、尺寸、使用场景、解决的问题 |
| 不要写促销文案 | 不要在描述里放"Free shipping"或"On sale now" |
| 不要关键词堆砌 | 不自然的关键词堆砌违反政策 |

### 2-5. Feed 更新与上传

| 方法 | 特点 | 适合 |
|---|---|---|
| 网址抓取（自动） | Google 定期从网址抓取 | 大目录、频繁更新 |
| 文件上传 | 手动上传 XML / CSV / TSV | 小目录、不常更新 |
| FTP / SFTP | 通过服务器自动发送 | 每天需要多次更新 |
| Content API / Merchant API | 程序化提交 | 需要实时更新 |

**更新频率规则：**
- **至少每 30 天**：必须重新提交 Feed（否则数据过期失效）。直接在商家中心注册的产品，或启用了 Google 商品自动更新时，行为有所不同。
- **建议每日更新。** 价格 / 库存不匹配是拒登的首要原因——频繁更新是最可靠的防御。
- 定时抓取的最小间隔为 **30 分钟**。

### 2-6. 补充 Feed

在不改主 Feed 的情况下新增或覆盖数据。

| 用途 | 说明 |
|---|---|
| 修复拒登 | 不动主 Feed，修补属性值 |
| 加自定义标签 | 添加由表现数据驱动的标签 |
| 加季节性属性 | 批量覆盖季节性属性 |
| 测试标题 / 描述 | 设置备选标题做 A/B 测试 |

## 3. 产品标题优化

产品标题是**购物广告最重要的优化点。** 它是 Google 把查询匹配到产品的首要信号，也是用户点击的决定因素。

### 3-1. 基本规则

| 规则 | 说明 |
|---|---|
| 最多 150 字符 | 但可见部分在约 70 字符处截断。**最重要的信息放在前 70 字符** |
| 与落地页产品名一致 | Feed 和落地页产品名不同有拒登风险 |
| 不要写促销文案 | "Free shipping"、"50% OFF"、"Sale" 等不属于标题 |
| 不要全大写 | 不要整个标题用大写 |
| 包含具体属性 | 品牌、颜色、尺寸、材质等提高搜索匹配准确度 |

### 3-2. 按品类的标题结构

最优标题结构取决于品类。

| 品类 | 建议结构 | 示例 |
|---|---|---|
| **服装** | 品牌 + 产品类型 + 性别 + 材质/特性 + 颜色 + 尺码 | Nike Running Jacket Women ClimaCool Blue M |
| **电子** | 品牌 + 产品名 / 型号 + 规格 + 特性 | Sony WH-1000XM5 Wireless Headphones Noise Cancelling Black |
| **家具 / 家居** | 产品类型 + 特性 + 材质 + 尺寸 + 颜色 | L-shaped Sofa Modern Velvet 3-Seater Navy |
| **食品 / 饮料** | 品牌 + 产品名 + 口味 / 品种 + 容量 + 数量 | Brand Name Green Tea 525 ml × 24 pack |
| **美妆 / 化妆品** | 品牌 + 产品名 + 类型 + 功效 + 容量 | SK-II Facial Treatment Essence Toner Hydrating 230 ml |

### 3-3. 标题优化技巧

- **品牌知名度高** → 品牌前置。
- **品牌知名度低** → 产品类型前置（被搜索的泛名词）。
- **同一产品的变体** → 标题中始终体现颜色 / 尺码差异。
- **结构化标题属性（`structured_title`）** → 支持标题优化的属性。可用性和范围会变化；依赖前先查当前商家中心规范。

## 4. 产品图片要求与最佳实践

购物 Feed/图片的通用指南用 [creative-strategy.md](creative-strategy.md#shopping--feed-creative-baseline)。购物专属的图片规则：

- 主图在缩略图尺寸下应清晰可辨。
- 与落地页上展示的产品变体一致。
- 避免促销叠加层、边框、水印，或只有误导性生活场景图。
- 在有助于购买信心时，用附加图片展示使用场景、细节、尺寸对比和套装。

## 5. 系列结构

### 5-1. 命名规范

一致的命名规范提高运营效率。

**建议格式：**

```
[地区] Shopping [品牌或非品牌] [产品品类] [年份]
```

**示例：**
- `US Shopping Non-Brand Furniture 2026`
- `US Shopping Brand Sofa 2026`
- `US Shopping Remarketing AllProducts 2026`

### 5-2. 系列拆分逻辑

| 拆分维度 | 原因 |
|---|---|
| 品牌搜索 vs 非品牌搜索 | 品牌搜索 CVR 更高；混在一起掩盖非品牌基线 |
| 按利润 | 把预算集中到高利润产品；压制低利润产品 |
| 爆款 vs 其余 | 隔离已验证的产品，积极出价 |
| 再营销 vs 拉新 | 用受众（观察模式）——对回访者加价，对新用户降价 |
| 季节 vs 常青 | 季节性加码预算更容易 |

**品牌 / 非品牌分离（购物专属）：**

购物广告不接受关键词输入，所以品牌 / 非品牌分离靠**系列优先级 + 否定关键词**实现。这不是硬拆分——是"投放引导"。

```
[非品牌系列]（优先级：高）
  ├── 把你的品牌名加为否定关键词
  ├── → 不带品牌名的查询优先走这里
  └── 出价：非品牌 CVR 更低——出价更保守

[品牌系列]（优先级：低）
  ├── 不加否定关键词（品牌词查询落到这里）
  ├── → 因为非品牌系列排除了品牌词，品牌搜索会流向这里
  └── 出价：品牌搜索 CVR 更高——加价
```

**注意：**
- 标准做法是在非品牌一侧加品牌词否定（反方向有误排除风险）。
- 无法做到完美分离。定期用搜索字词报告检查泄漏。
- 排除竞品品牌名时要谨慎——有法律和政策考量。

### 5-3. 建议的系列结构模板

对电商店家，基础的 3 系列结构：

```
[标准购物] 爆款
  ├── 产品组：custom_label = bestseller
  ├── 出价：手动 CPC（高）→ 迁移到目标 ROAS
  ├── 预算分配：总预算的 50%
  └── 优先级：高

[标准购物] 常规产品
  ├── 产品组：除爆款外的所有产品
  ├── 出价：手动 CPC（标准）→ 迁移到争取更多转化
  ├── 预算分配：总预算的 35%
  └── 优先级：中

[标准购物] 测试 / 新品
  ├── 产品组：custom_label = new_arrival
  ├── 出价：手动 CPC（低）
  ├── 预算分配：总预算的 15%
  └── 优先级：低
```

### 5-4. 预算指南

**日预算逻辑：**

没有足够的日点击，AI 学习和表现评估都缺数据。目标是**每天至少 10 次点击**。

```
预估 CPC × 10（最低点击目标）= 最低日预算
```

示例：预估 CPC $0.30 → 最低日预算约 $3/天。

> 这个公式是"最低数据积累"用的。要优化转化，预算需要高得多。

**按规模分配预算：**

| 月预算 | 建议结构 |
|---|---|
| 约 $2,000 以内 | 单个标准购物系列 |
| 约 $2,000–$7,000 | 爆款 + 常规（2 个系列） |
| 约 $7,000–$20,000 | 3 系列结构 + 考虑加 PMax |
| 约 $20,000 以上 | 3 系列 + PMax + 品牌防守系列 |

## 6. 购物专属出价

### 6-1. 设置手动 CPC

**最高 CPC 公式：**

```
最高 CPC = 产品价格 × 毛利率 × CVR
```

示例：产品价格 $100，利润率 40%，CVR 2%
→ 最高 CPC = $100 × 0.40 × 0.02 = **$0.80**（盈亏平衡）

**初始出价从盈亏平衡的 50–75% 开始**，按表现调整。

### 6-2. 从手动迁移到智能出价

| 阶段 | 条件 | 动作 |
|---|---|---|
| 1. 手动 CPC 起步 | — | 在产品组层级手动出价。优先积累数据 |
| 2. 数据积累 | 30+ 转化 | 识别出价表现趋势 |
| 3. 测试智能出价 | 转化历史稳定 | 先用草稿以目标 ROAS 或目标 CPA 预测试 |
| 4. 迁移到智能出价 | 测试结果为正 | 全面迁移。按实际历史设定目标 |

**重要：不要在全新系列上设目标 ROAS。** 转化数据不足时，AI 学习不稳定——投放要么大幅下滑，要么低效放量。

### 6-3. 出价调整逻辑

**按利润出价：**

| 利润 | 出价姿态 | 示例 |
|---|---|---|
| 高（60%+） | 积极 | 最高 CPC 的 75–100% |
| 中（30–59%） | 标准 | 最高 CPC 的 50–75% |
| 低（<30%） | 保守 | 最高 CPC 的 25–50% |

**受众（观察）出价调整：**

在购物广告中，受众可以以"观察"模式加入并应用出价调整。注意：智能出价下，出价调整会被自动吸收为信号——不需要手动调整。

| 受众 | 出价调整指南（手动 CPC 下） |
|---|---|
| 加购未买 | +50% |
| 产品页浏览者 | +25% |
| 全站访客 | +10% |

> 类似受众已于 2023 年 8 月下线。用智能出价信号优化或客户匹配代替。

### 6-4. 系列优先级

在标准购物中，当**同一产品在多个系列中**，优先级决定哪个系列出价。

| 优先级 | 出价逻辑 |
|---|---|
| **高** | 先出价；优先于其他优先级 |
| **中** | 高优先级系列预算受限时出价，或产品不在高优先级系列中时出价 |
| **低** | 高和中都预算受限时出价。默认设置 |

**同一优先级** → 出价高的胜出。

## 7. 产品组与否定关键词

### 7-1. 产品组设计

在购物广告中，你不按关键词出价——而是通过**产品组**出价。

**可用的细分属性：**

| 属性 | 说明 | 用途 |
|---|---|---|
| 品类 | Google 的产品分类体系 | 顶级品类 → 中级品类的层级 |
| 品牌 | 品牌名 | 自有品牌 vs 经销品牌 |
| 产品类型 | 你自己的分类体系 | 非常灵活的分类 |
| 自定义标签 | custom_label_0–4 | 利润 / 季节 / 表现等 |
| 产品 ID | 单个 SKU | 针对爆款产品单独出价 |
| 状况 | new / refurbished / used | 按状况调整出价 |

**建议的层级：**

```
所有产品
├── 品类：家具
│   ├── custom_label: bestseller → 出价：高
│   ├── custom_label: regular → 出价：中
│   └── custom_label: clearance → 出价：低
├── 品类：电子
│   ├── custom_label: bestseller → 出价：高
│   └── ...
└── 其余全部 → 出价：低（兜底）
```

**"其余全部"一定要设出价。** 否则未分类的产品会按默认出价花钱。

### 7-2. 否定关键词

购物广告无法通过关键词控制展示，所以**否定关键词是控制搜索查询的唯一手段。**

**否定关键词范围：**

| 层级 | 范围 |
|---|---|
| 系列级 | 作用于系列内所有产品组 |
| 广告组级 | 只作用于特定广告组 |

**匹配类型：**

| 匹配类型 | 符号 | 说明 |
|---|---|---|
| 宽泛 | `keyword` | 默认。查询中包含该词即生效，不论词序 |
| 短语 | `"keyword"` | 查询中包含完整短语时生效 |
| 精确 | `[keyword]` | 只在精确匹配的查询上生效 |

**初始否定关键词示例：**

| 类别 | 示例 |
|---|---|
| 无购买意图 | free、DIY、how-to、tutorial、repair、review、comparison |
| 竞品 / 他人 | （按实际情况）竞品名 / 竞品品牌名 |
| 不相关的产品 | 你不卖的品类或类型 |
| 二手 / 不想要 | used、junk、"looking to sell" |

### 7-3. 使用搜索字词报告

- **每周**检查。
- 把不相关或不转化的查询加入否定词。
- 发现高表现的查询 → 考虑并入产品标题。

## 8. 政策与审核

购物政策工作主要是 Feed 卫生加品类合规。受管制产品上线前，先查当前商家中心政策和各国限制。

| 原因 | 成因 | 修复 |
|---|---|---|
| 禁止类产品 | 假货、危险品、不诚信行为服务、不当内容 | 从 Feed 删除并在上游防止复发 |
| 受限类产品 | 酒类、成人用品、医疗/药品、高糖高盐高脂食品饮料、其他受管制品类 | 确认各国规则、必填属性、认证和定位限制 |
| 价格不匹配 | Feed 和落地页价格不同 | 提高 Feed 更新频率。实现结构化数据（schema.org） |
| 库存不匹配 | Feed 显示 `in_stock` 但落地页无货 | 实现库存联动的自动 Feed 更新 |
| 图片问题 | 尺寸太小、文字叠加、占位图 | 按第 4 节替换图片 |
| GTIN / MPN 错误 | 标识符错误或缺失 | 用 GTIN 验证器校验。定制商品声明 GTIN 豁免 |
| 404 落地页 | 链接损坏 | 实现网址监控；提交 Feed 前检查链接 |
| 运费信息问题 | 运费 / 时效未配置 | 完整填写 GMC 运费设置 |
| 政策违规内容 | 禁止 / 受限类目商品 | 从 Feed 删除违规产品 |

如果不服拒登：
1. 在 GMC 的"诊断"标签页查看拒登原因。
2. 修复问题并重新提交 Feed。
3. 等待重新审核（通常 3–5 个工作日）。
4. 如果理由正当，用"申请审核"选项请求审核。

**避免账户被封：** 反复拒登会导致账户被封。早处理错误和警告——不要置之不理。

## 9. 测量与评估

### 9-1. 转化设置

对于购物（电商），准确跟踪转化价值（收入）尤其重要。

| 设置 | 建议 |
|---|---|
| 主要转化 | 购买完成 |
| 转化价值 | **每笔交易发送动态的实际收入值** |
| 归因 | 数据驱动归因（DDA） |
| 转化测量窗口 | 点击后 30 天（默认）。高客单价商品考虑 60–90 天 |

### 9-2. 关键 KPI

| 指标 | 定义 | 指南 |
|---|---|---|
| ROAS | 转化价值 ÷ 广告花费 | 盈亏平衡 ROAS = 1 ÷ 利润率（30% 利润率 → 333%；40% → 250%；50% → 200%）。目标 ROAS 设在盈亏平衡之上 |
| CTR | 点击 ÷ 展示 | 行业平均因行业而异；作为改进基准 |
| CVR | 转化 ÷ 点击 | 很大程度上取决于落地页质量和价格竞争力 |
| CPC | 花费 ÷ 点击 | 因品类和竞争而异 |
| 展示份额 | 展示 ÷ 符合条件的展示 | 反映预算 / 出价是否充足 |

### 9-3. 按利润评估

不要只看 ROAS 评估——要按**毛利盈利能力**评估。

```
广告利润 =（收入 × 利润率）− 广告花费
```

示例：
- 收入 $10,000，利润率 40%，广告花费 $2,500
- 广告利润 = ($10,000 × 0.4) − $2,500 = **$1,500**
- ROAS = 400%（看起来不错，但在更低的利润率下，400% ROAS 仍可能亏钱）

### 9-4. 常见测量陷阱

| 陷阱 | 问题 | 修复 |
|---|---|---|
| Google Ads 转化与 GA4 转化对不上 | 归因、测量窗口、计数方式不同 | **出价优化以 Google Ads 的购买转化数据为准；** GA4 用于用户行为分析 |
| 主要 / 次要转化混淆 | 主要转化驱动出价优化。把不需要的转化放进主要会破坏学习 | **只有购买完成是主要的。** 微转化（加购等）放次要 |
| 未启用增强型转化 | Cookie 限制导致转化漏计越来越多 | 通过增强型转化哈希并发送第一方数据（邮箱等） |
| 报告指标不一致 | 收入 ROAS 和毛利 ROAS 会导致不同决策 | 统一三个指标：**收入 ROAS**（Google Ads 界面）、**毛利 ROAS**（毛利 ÷ 广告花费，单独计算）、**广告利润**（毛利 − 广告花费） |

### 9-5. 产品级分析

定期在产品层级检查：

| 分桶 | 条件 | 动作 |
|---|---|---|
| 胜出者 | ROAS 达到或超过目标，转化稳定 | 加价、加预算 |
| 培育中 | 展示高、转化少 | 优化标题 / 图片 / 落地页 |
| 烧钱坑 | 花费高、零转化 | 降价或排除 |
| 无曝光 | 展示接近零 | 加价、改进标题 |

## 11. 标准购物 vs Performance Max

### 11-1. 对比表

| 项目 | 标准购物 | Performance Max |
|---|---|---|
| 展示位置 | 搜索结果、购物标签页、图片搜索 | 搜索、购物、展示、YouTube、Gmail、Discover、地图 |
| 关键词控制 | 支持否定关键词 | 支持系列级否定词；当前系列级上限为 10,000。支持共享否定关键词列表。 |
| 搜索字词报告 | 详细的搜索字词报告 | "搜索字词洞察"（概览层级） |
| 出价控制 | 支持手动 CPC | 仅智能出价 |
| 产品组控制 | 详细的产品组设置 | 素材资源组 + 列表组 |
| 必需素材 | 只需产品 Feed | 只用产品 Feed 也足以启动；文本 / 图片 / 视频素材会自动生成，也可自行提供以扩大覆盖（[Google Ads 帮助](https://support.google.com/google-ads/answer/10724817)） |
| 建议转化数 | 无硬性最低要求 | 建议每月 30+ |
| 透明度 | 高 | 低于标准购物 |

### 11-2. 优先级逻辑变更（2024）

**之前：** 同一产品，PMax 自动优先于标准购物。

**现在：** 由**广告评级**决定。同一产品同时存在时，竞价时刻广告评级更高的系列胜出。

这一变更恢复了标准购物的竞争力，混合运行（两者都跑）更有效了。

> 这一变更在各账户的具体生效时间可能不同。用搜索字词报告在自己的账户中验证行为。

### 11-3. 何时用哪个

| 情况 | 建议 |
|---|---|
| 刚上线、转化数据少 | 标准购物（积累数据、学习） |
| 需要详细的搜索字词分析 | 标准购物 |
| 需要细粒度手动出价控制 | 标准购物 |
| 想要所有版位的最高覆盖 | Performance Max |
| 转化数据充足（每月 30+） | 考虑加 Performance Max |
| 文本 / 图片 / 视频素材已就绪 | Performance Max |

### 11-4. PMax 控制手段

PMax 自动化程度高，但你仍有以下手段。

**如何拆分素材资源组：**

| 拆分维度 | 示例 | 好处 |
|---|---|---|
| 按产品品类 | 家具 / 电子 / 服装 | 每个品类配文本和图片素材 |
| 按利润 | 高利润 vs 低利润 | 按利润设不同的目标 ROAS |
| 新客获取 vs 再营销 | 新客目标开 / 关 | 分开受众，用不同的获客成本 |

**列表组设计：**

与标准购物的产品组一样——在 PMax 中用列表组收窄产品。用自定义标签或品类拆分，每个素材资源组投放不同的产品集。

**看不到搜索字词时的改进方法：**

PMax 不提供详细的搜索字词报告。用这些信号代替：
- **搜索字词洞察**：按品类的搜索主题和展示次数
- **按产品表现**：按各产品的 ROAS / 转化 / 花费判断胜负
- **按素材表现**：按文本 / 图片 / 视频的"最佳 / 良好 / 差"评级判断替换

### 11-5. 混合运营

**建议做法：**

1. **阶段 1（第 1–4 周）：** 只跑标准购物。积累基线数据。
2. **阶段 2（第 2 个月起）：** 标准购物稳定盈利后，加 PMax。
3. **持续：** 在标准购物中优化已知的胜出产品；在 PMax 中扩大新客获取。

- 标准购物 = **对已知胜出模式的收割**
- Performance Max = **新发现和覆盖扩展**

## 12. 免费商品展示

### 12-1. 概述

2020 年上线——免费的商品展示位。不投付费广告，只把产品 Feed 提交到 GMC，产品就能出现在 Google 的版位上。

**展示位置：**
- Google 购物标签页
- Google 搜索（部分）
- Google 图片搜索
- Google Lens

### 12-2. 与付费广告的区别

| 项目 | 付费购物广告 | 免费商品展示 |
|---|---|---|
| 费用 | CPC（按点击付费） | 免费 |
| 位置 | 购物轮播顶部 | 购物标签页付费广告下方 |
| 控制 | 可控制出价和预算 | 算法驱动 |
| 流量规模 | 大（轮播占据大部分点击） | 比付费小 |

### 12-3. 可利用的商家中心能力

能提升购物广告的 GMC 附加功能。

**商家促销：**

在产品上展示"特价" / "免运费"促销徽章，提升 CTR。

| 设置 | 说明 |
|---|---|
| 促销 Feed | 在 GMC 注册促销信息。用 `promotion_id` 关联产品 |
| 范围 | 全部产品或特定产品（把 `promotion_id` 映射到 Feed） |
| 条件 | 金额折扣、百分比折扣、免运费、买一送一等 |
| 定位 | 新客专享或按区域等条件 |

**产品评分：**

在产品上展示星级评分——点击决策的助推器。

- 通过 Google 客户评价或第三方评价服务获得
- 最低要求：每个产品最少评价数（因国家而异）
- 向 GMC 提交评价 Feed（XML）

**商品自动更新：**

- Google 抓取你的网站，自动修正 Feed 与网站的价格 / 库存差异
- 启用后降低拒登风险，但可能出现非预期的修正
- **建议：** 启用，但 Feed 本身也要每日更新（自动更新只是补充）

**价格 / 库存一致性监控：**

- 在落地页上实现结构化数据（schema.org `Product` 标记：`price`、`availability`）——提高 Google 自动校验的准确度
- 用外部工具或自有脚本监控 404 和价格不匹配；能有效防止拒登

### 12-4. 优化免费商品展示

不投付费广告，提高 Feed 质量也能增加免费商品展示的曝光。

- 填全所有建议属性（GTIN、google_product_category、颜色、尺寸等）
- 优化标题和描述（第 3 节）
- 用高质量图片（第 4 节）
- 提高 Feed 更新频率（建议每日）
- 接入产品评价 / 评分

## 13. 常见失败模式与应对

| # | 失败 | 成因 | 应对 |
|---|---|---|---|
| 1 | 全新系列上设目标 ROAS | 转化数据不足；AI 学不会 | 从手动 CPC 开始；30+ 转化后再迁移 |
| 2 | 产品标题短而泛 | 搜索匹配准确度低；错失展示 | 按品类标题结构，带全相关属性 |
| 3 | Feed 每月或更久才更新 | 价格 / 库存不匹配导致拒登 | 自动化每日更新 Feed |
| 4 | 没有否定关键词 | 花费泄漏到不相关查询 | 初始否定词 + 每周检查搜索字词 |
| 5 | 让"其余全部"按默认出价跑 | 未分类的低表现者浪费花费 | 设低出价或从 Feed 排除 |
| 6 | 不用自定义标签 | 无法按利润 / 季节出价 | 至少按利润和销售表现打标签 |
| 7 | 所有产品在一个系列 | 高低利润产品共用一个出价 | 按利润 / 表现拆分系列 |
| 8 | 图片质量低、尺寸小 | CTR 下滑；竞争力受损 | 提供 1,500×1,500 px 或更大的高质量图片 |
| 9 | 落地页不是产品页 | 用户被送到品类页或首页，留存受损 | Feed 的 `link` 设为单个产品页网址 |
| 10 | 只选标准购物或只选 PMax | 错过另一方的优势 | 混合：收割 + 探索 |
| 11 | 不用促销 | 错过 CTR 提升（不显示徽章） | 用 GMC 促销（提升 CTR） |
| 12 | "设置后不管" | 跟不上市场和竞品变化；表现衰减 | 按每日 / 每周 / 每月节奏检查 |
