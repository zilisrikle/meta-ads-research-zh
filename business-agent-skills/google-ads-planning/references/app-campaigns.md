# Google 应用广告系列（App Campaigns）

## 运营实践

应用广告系列的自动化程度极高。真正的杠杆是事件选择、事件质量、预算-出价比、创意多样性、地域 / 平台拆分，以及学习期的耐心。

### 最重要的事

- **选最深层的、有稳定量级的事件，而不是可选的最深层事件。** 只有购买足够频繁时，对购买出价才是对的。不够就用一个与 LTV 相关的代理事件（proxy event），并审计这个相关性。
- **创意是主要的可控杠杆。** 上差异化概念，尤其要上视频。应用广告系列需要覆盖不同动机、使用场景、异议、游戏 / 产品时刻和用户利益的多样性。
- **预算-出价比很重要。** 预算不足的 tCPI / tCPA 广告系列没法参与足够多的竞价探索。先按设置指引做，再谈算法诊断。
- **不要把价值不等动作混在一个目标下。** 如果试用开始、订阅、购买、教程完成的价值不同，定义好价值，或谨慎选择核心事件。
- **iOS 归因对不上是正常的。** SKAN、MMP 和 Google 上报的数字可能分叉。各有各的用处：SKAN 给方向性的隐私安全真相，MMP 做跨网运营，Google 数字代表出价现实。
- **ACe 要对增量性保持怀疑。** 再营销广告系列可能截获本来就会自然回来的用户。利害攸关时用对照组或保守口径汇报。
- **学习很容易被破坏。** 换出价目标、预算、地域或整批换创意都会重置动量。创意逐渐加，目标调整要果断但克制。

- **上线时浅，成熟了再深。** 冷启动获客可以用 tCPI 或高量级的应用内事件先养学习；深层事件有稳定量级且价值可靠时，再迁到 tCPA / tROAS。
- **代理事件需要业务验证。** 教程完成、加购、付费墙浏览、过关、试用开始，只有与留存 / LTV 相关才有用。定期审计这个相关性。
- **视频更新通常是创意的首要任务。** 文案素材寿命可以更长；视频疲劳出现得更早，尤其在放量时。
- **不要把剪辑版本当创意多样性。** 同一个想法的多种时长或比例有助于覆盖版位，但算法还需要不同的动机、使用场景、情感钩子和信任状。
- **ACe 应该做增量性测试。** 回流用户常常不打广告也会回来。放量之前先用受众对照组、地域测试或保守归因，而不是只看平台 ROAS 就放量再营销。
- **有网站流量时，Web-to-App Connect 是战略杠杆。** 深度链接、事件传递和归因打通的运营成本高，但当同一批用户在网站发现、在应用转化时，能提升用户质量。
- **季节性高峰需要提前规划目标。** 如果 CPM / CPI 可预测地上涨，在高峰到来前调整目标和预算，而不是高峰中途再反应。

### 诊断

| 症状 | 先查 | 可能的行动 |
|---|---|---|
| 有安装但质量差 | 优化事件、安装后漏斗、MMP / Firebase 映射 | 量级够就往深迁，提升事件质量，用价值出价 |
| 花不出去 | 预算-出价比、应用资格、政策、地域、出价目标 | 提高预算 / 目标，修资格，放宽地域 / 素材 |
| tROAS 不稳定 | 购买量级、价值口径、广告系列拆分 | 用代理事件、合并、修价值映射 |
| iOS 数字对不上 | SKAN 口径、SDK 初始化、回传时机、MMP 映射 | 正常差距当方法论差异处理；差距大再调查 |
| 创意疲劳 | 素材评分、花费集中度、概念上线时长 | 加新视频 / 新概念系列，不只是剪辑版本 |

### 常见陷阱

- 留存或收入才是真实目标，却永远对安装优化。
- 购买 / 价值量级还没稳定就跳上 tROAS。
- 上传同一个创意概念的很多剪辑版本，当作多样性。
- 学习期初期数据看起来很吵，就换目标、换创意。

## 广告系列类型速查表

| 目标 | 广告系列类型 | 出价策略 | 日预算指引 | 主要版位 |
|---|---|---|---|---|
| **新用户获取** | ACi（安装优化） | tCPI | tCPI × 50 或更高 | 搜索、Play、YouTube、展示等 |
| **应用内行为获取** | ACi（行为优化） | tCPA | tCPA × 10 或更高 | 搜索、Play、YouTube、展示等 |
| **收入最大化** | ACi（ROAS 优化） | tROAS | 充足的预算 | 搜索、Play、YouTube、展示等 |
| **老用户再营销** | ACe | tCPA | tCPA × 15 或更高 | 搜索、YouTube、展示等 |
| **上线前预注册** | ACpre | 预注册成本 | 预注册成本 × 50 或更高 | Play、YouTube、展示等 |

> **注意：** 版位可能随平台更新变化或扩展（例如 Discover）。

## 1. 版位与基本特性

广告主只能控制三件事：素材（创意）、预算、出价目标。其他全部由 Google 的 AI 自动化。

| 版位 | 展示位置 | 特点 |
|---|---|---|
| **Google 搜索** | 搜索结果页 | 在应用相关搜索词上展示文字广告 |
| **Google Play** | 应用内搜索结果和推荐 | 触达安装意向最高的用户 |
| **YouTube** | 信息流内、Feed、Shorts | 由视频素材驱动。覆盖量最大 |
| **展示网络** | 应用内广告、移动网站 | 广泛的受众覆盖 |

## 2. 前置条件

| 项目 | 要求 |
|---|---|
| 应用商店页面 | 已在 Google Play 或 App Store 上架（ACpre 除外） |
| 衡量 SDK | 已接入 Firebase SDK 或 MMP（AppsFlyer、Adjust 等） |
| 转化跟踪 | 安装和 / 或应用内事件的跟踪已部署 |
| 日预算 | 能支撑 tCPI × 50 或 tCPA × 10 |
| ACe（互动）的额外要求 | 有意义的安装基数、已实现深度链接、且在广告系列创建流程中可选 ACe。具体要求因账户和类目而异 |

### 2-3. 上线前检查清单

- [ ] 应用商店页面已优化（截图、描述、预览视频）
- [ ] Firebase SDK 或 MMP 正确接入
- [ ] Google Ads ↔ Firebase / MMP 集成完成；核心出价事件的数据源已定（Firebase 或 MMP）
- [ ] 要导入的转化清单（Primary / Secondary）已定稿
- [ ] 最低创意套装：10 条文案素材（5 标题 + 5 描述）、4 张以上图片、2 条视频（16:9 + 9:16）
- [ ] 预算满足出价 × 最低倍数的要求
- [ ] iOS 侧团队已就判断窗口达成一致（≥7 天，考虑 SKAN 延迟）
- [ ] 应用商店（ASO）更新的负责人和节奏已定（ASO 直接影响自动生成素材的质量）
- [ ] 深度链接已实现并测试（ACe 用）

## 3. 选择广告系列类型

### 3-1. ACi（应用安装广告系列）

最基础的类型，聚焦新用户获取。

**优化目标选项：**

| 优化目标 | 出价策略 | 建议条件 |
|---|---|---|
| 安装量 | tCPI | 早期、转化量级低；想先起量 |
| 应用内行为 | tCPA | 预计每天 30+ 目标事件 |
| 应用内行为价值 | tROAS | 有充足的购买 / 收入数据 |

**分阶段迁移路径：**

```
tCPI（安装优化）
  ↓ 每天稳定 30–50+ 应用内行为
tCPA（行为优化）
  ↓ 积累了充足的购买 / 收入数据
tROAS（收入优化）
```

### 3-2. ACe（应用互动广告系列）

老用户再营销。

**资格（粗略指引，因账户和类目而异）：**
- 有意义的安装基数（粗略指引：50,000+；以前是 250,000，现在放宽了）
- 已实现深度链接（App Links / Universal Links / 自定义 scheme）
- 有应用用户受众列表

> **验证方法：** 最可靠的办法是看 Google Ads 广告系列创建流程里有没有 ACe 选项。

**常见用途：**

| 用途 | 说明 |
|---|---|
| 唤回沉睡用户 | 向 7 天以上没打开应用的用户投放 |
| 挽回弃购 | 用深度链接把没完成购买的用户带回商品页 |
| 推动应用内购买 | 向免费用户推销付费内容 |
| 活动 / 促销通知 | 限时活动用深度链接直达应用内页面 |

**深度链接类型与优先级：**

| 类型 | 平台 | 建议 |
|---|---|---|
| App Links | Android | 最推荐 |
| Universal Links | iOS | 最推荐 |
| 自定义 scheme | iOS / Android | 作兜底 |

### 3-3. ACpre（应用预注册广告系列）

上线前的预注册广告系列。**仅 Android。**

**前置条件：**
- 应用已在 Google Play Console 开启预注册
- 至少一个 APK 已上传到发布轨道
- 计划在预注册开启后 90 天内上线

**建议时机：** 计划上线前 3–6 周开启预注册，同时启动广告系列。

**版位：** Google Play、YouTube（仅信息流内）、展示网络。

**注意：** 应用上线后，已上线地区的广告系列会自动暂停投放。

## 4. 搭建衡量基础

### 4-1. 选择跟踪方案

| 方案 | 平台 | 说明 |
|---|---|---|
| **Firebase SDK** | iOS / Android | Google Ads 出价信号和受众搭建的强基线集成 |
| **Google Play 安装引荐来源** | 仅 Android | 轻量衡量 Google Play 的安装路径 |
| **MMP** | iOS / Android | AppsFlyer、Adjust、Singular 等。跨平台衡量最强 |

**建议：** 以 Firebase SDK 为基线，按需叠加 MMP。Firebase SDK 对 Google Ads 依赖的出价信号和受众搭建有独特能力，和 MMP 并行不冲突。

### 4-2. 设计转化事件

**事件选择原则：** 质量优先于数量。不要只对安装优化——选有真实业务价值的应用内事件。

| 事件类型 | 示例 | 用途 |
|---|---|---|
| 安装 | first_open | 默认的 ACi 优化目标。Android 自动跟踪 |
| 轻事件 | 教程完成、资料创建 | 初期 tCPA 目标（要量级） |
| 中事件 | 加购、过关、搜索 | 用户质量稳定后的优化目标 |
| 深事件 | 购买、订阅开始、付费行为 | 最终优化目标。需要充足量级 |

**事件量级指引：**

| 层级 | 每日事件数 | 状态 |
|---|---|---|
| 最低 | 10 / 天 | 广告系列能学习的最小量 |
| 建议 | 30–50 / 天 | 稳定优化 |
| 理想 | 100+ / 天 | 高精度优化。也有助于越过 iOS SKAN 隐私阈值 |

### 4-3. Firebase 规划检查项

实施细节归 Firebase / 应用分析文档。本手册只做 Google Ads 规划层面的确认：

| 检查项 | 为什么重要 |
|---|---|
| Firebase 和 Google Ads 已关联 | Google Ads 收到应用事件和受众的前提 |
| 核心出价事件的数据源明确 | 防止 Firebase 和 MMP 重复导入 |
| 目标事件命名和映射一致 | 防止各团队对广告系列目标各说各话 |
| 事件量级支撑所选出价策略 | 事件太稀，tCPA / tROAS 会不稳定 |

### 4-4. Firebase + MMP 并行

Firebase 和 MMP（AppsFlyer、Adjust 等）可以并行，各有优势：

| 角色 | Firebase | MMP |
|---|---|---|
| Google Ads 出价信号 | 最优 | 支持 |
| 受众搭建 | Firebase 独有功能 | 不支持 |
| 跨平台衡量 | 有限 | 核心能力 |
| 多渠道归因 | 以 Google 为中心 | 全渠道 |

### 4-5. 并行时避免重复计数

Firebase 和 MMP 并行时，同一个转化事件（例如购买）从两边都导入 Google Ads 会造成重复计数，破坏出价优化和报表。

**预防规则：**

| 规则 | 说明 |
|---|---|
| 用于出价的核心事件只定一个数据源 | 决定从 Firebase 还是从 MMP 导入——二选一 |
| 同名事件不要导入两次 | 不要同时有 Firebase-purchase 和 MMP-purchase 两个 Primary |
| Primary vs Secondary 角色明确 | 用于出价优化的事件 → Primary。只做报表的事件 → Secondary |
| 事件命名标准化 | 维护团队级映射表，把 Firebase / MMP 事件名对应到各自角色 |

## 5. 设计广告系列结构

### 5-1. 核心原则

应用广告系列结构最重要的原则：**默认合并；只有理由充分才拆分。**

过度拆分会碎片化数据，降低 AI 学习效率。

### 5-2. 拆分广告系列的时机

| 拆分维度 | 理由 | 示例 |
|---|---|---|
| **按系统** | iOS / Android 的衡量和优化本质不同 | iOS / Android |
| **按优化目标** | tCPI 和 tCPA 不能共存于同一广告系列 | 安装 / 行为 |
| **按地域** | LTV 或 CPI 差异很大的地区值得单独做 | 日本 / 东南亚 / 北美 |
| **按语言** | 创意需要按语言区分时 | 日语 / 英语 |

**注意：** 不要跑多个同地域、同优化目标的广告系列——会互相蚕食、推高 CPI。

**iOS 运营建议：** 原则上 iOS 广告系列保持在 8 个左右或更少。这不是平台上限，而是防止信号碎片化的运营指引。只有地域、语言或优化目标差异足够大时才破例。

### 5-3. 设计广告组

围绕**创意主题**建广告组。

| 主题示例 | 素材内容 |
|---|---|
| 功能导向 | 突出应用核心功能 |
| 用户利益 | 用户能得到的价值 |
| 社会认同 | 评价、评分、下载量 |
| 促销 | 限时优惠、新人福利 |

**每广告组素材上限：**

| 素材类型 | 上限 | 建议 |
|---|---|---|
| 文案（标题） | 5 | 5（填满） |
| 文案（描述） | 5 | 5（填满） |
| 图片 | 20 | 至少 4 张以上 |
| 视频 | 20 | 至少 2 条（竖版 + 横版） |
| HTML5 | 20 | 仅游戏应用 |

### 5-4. 推荐结构示例

**基础结构（单地区、Android）：**

```
Account
└── ACi - JP - Install
    ├── Ad group: Feature-focused
    ├── Ad group: Benefit-focused
    └── Ad group: Social proof
```

**中型结构（iOS + Android、多地区）：**

```
Account
├── ACi - Android - JP - Install (tCPI)
│   ├── Ad group: Feature-focused
│   └── Ad group: Promotion
├── ACi - Android - JP - Action (tCPA)
│   ├── Ad group: Paid-content-focused
│   └── Ad group: Benefit-focused
├── ACi - iOS - JP - Install (tCPI)
│   └── Ad group: Feature-focused
├── ACe - Android - JP - Re-engagement (tCPA)
│   └── Ad group: Dormant-user-focused
└── ACi - Android - SEA - Install (tCPI)
    └── Ad group: English-language-focused
```

## 6. 出价与预算设计

### 6-1. 选择出价策略

| 出价策略 | 优化目标 | 建议条件 | 预算 / 出价比 |
|---|---|---|---|
| **tCPI** | 安装量 | 早期、转化量级低 | 日预算 ≥ tCPI × 50 |
| **tCPA（新用户）** | 应用内行为 | 每天 30+ 事件 | 日预算 ≥ tCPA × 10 |
| **tCPA（老用户，ACe）** | 再营销行为 | 已有用户基数 | 日预算 ≥ tCPA × 15 |
| **tROAS** | 转化价值 | 有充足的购买数据 | 充足的预算 |

### 6-2. 设定初始出价

**tCPI：**
- 调研该应用类目的平均 CPI（国家和类目差异极大）
- 初始出价设为类目平均的 80–100%
- 容忍 1–2 周学习期的 CPI 偏高

**tCPA：**
- 用观测到的 CPA（来自 Firebase / MMP）作为起点
- 初始出价与观测值持平或略高

### 6-3. 为什么预算-出价比重要

应用广告系列的 AI 从预算-出价的平衡里读信号。比例太低意味着：
- 每日投放量太小——学习数据不够
- 状态变成"预算受限"，无法最优投放

| 出价策略 | 最低比例 | 建议比例 |
|---|---|---|
| tCPI | 50× | 100× |
| tCPA（新用户） | 10× | 20× |
| tCPA（ACe） | 15× | 20× |

### 6-4. 学习期运营

**学习期：** 新广告系列创建后大约 1–2 周。

**学习期规则：**
- 不改出价和预算
- 不做大的创意改动
- 不改定向
- 容忍短期 CPI / CPA 冲高
- 不用少于 2 天的数据做决策（iOS 尤其）

**学习完成信号：** CPA 稳定 5–7 天。

### 6-5. 跑 tROAS 时定义转化价值

用 tROAS 时，团队必须就发送的 `value`（转化价值）定义达成一致。定义漂移，优化就崩。

**要明确的事项：**

| 事项 | 确认什么 |
|---|---|
| 收入事件范围 | 包含哪些：应用内购买、订阅、广告收入 |
| `value` / `currency` 发送规则 | 含税还是不含税、折后金额、货币代码 |
| 退款处理 | 退款时发负价值，还是作为单独事件管理 |
| 订阅区分 | 区分 trial_start（免费试用开始）和 paid_start（付费开始）。默认按"发生付费"优化；量级不够时才后退 |

## 7. 应用创意素材

制作规格见 [creative-strategy.md](creative-strategy.md#app-campaign-baseline)。规划规则：

- 文案素材要自成一体、长短搭配，围绕不同动机或异议来写。
- 图片展示应用界面或产品时刻；避免只有泛泛的生活方式图。
- 视频是放量的第一创意优先级。尽量覆盖横版、方版、竖版。
- 用 ABCD 逻辑：早钩子、早出现应用 / 品牌、连接用户动机、明确的行动收尾。
- 如果没上传视频，Google 可能用商店素材自动生成；那是兜底，不是创意策略。
- 可玩 / HTML5 广告主要适用于游戏，或互动能实质提升用户质量的应用。工具、SaaS、内容类应用通常不需要。

## 8. 素材运营与广告效力（Ad Strength）

### 8-1. 广告效力

每个广告组的广告效力保持"良好"或以上。

**广告效力评估标准：**
- 素材数量和多样性充足
- 素材差异化（主题和版式）
- 符合 Google 最佳实践

### 8-2. 评估素材表现

每条素材会有一个表现评分：

| 评分 | 含义 | 做法 |
|---|---|---|
| **Learning** | 还在收集数据 | 不动。至少等几天到一周 |
| **Low** | 同类型中表现最低 | 考虑换新素材替换 |
| **Good** | 表现稳定 | 保留。考虑加类似变体 |
| **Best** | 表现最高 | 沿这个方向做新变体 |

**评分使用注意：** 不要只看评分做决策。结合以下 KPI 综合判断。

| KPI | 看什么 |
|---|---|
| 表现评分 | Learning / Low / Good / Best |
| 花费占比 | 花费少的素材可能输给了 Google 自动生成的素材 |
| 展示量 | 投放量不够的评分不可靠 |
| CPI / CPA | 每条素材的成本效率 |
| CVR | 每条素材的转化率 |

**决策逻辑：**
- "Best" + 高花费 + CPI / CPA 可接受 → 沿这个方向做新变体
- "Low" + 高花费 → 优先替换（成本影响大）
- "Low" + 低花费 → 可能是学习不够。再观察一阵或替换
- 0 花费 → Google 更偏好自动生成的素材。检查该素材的质量和版式

### 8-3. 素材更新规则

| 规则 | 原因 |
|---|---|
| 克制更新（粗略指引：每周 1–2 次） | 频繁改动重置 AI 学习。优先保住当前学习 |
| 不要一次换掉所有素材 | 对比数据就没了 |
| 沿"Best"方向做新变体 | 把赢的模式横向放大 |
| 优先替换"Low"素材 | 改进影响最大 |
| 保持主题多样性 | AI 能服务多样的版位和用户 |

## 9. iOS 广告系列注意事项

### 9-1. ATT（应用跟踪透明度）的影响

iOS 14.5 起，ATT 弹窗要求用户授权。典型授权率约 15–30%，实际因应用类目、地区和弹窗设计差异极大。

**影响：**
- 大部分转化数据变成模型化（估算）数据
- 数据最长可能延迟 5 天才出现
- 优化精度低于 Android

### 9-2. SKAdNetwork（SKAN）

苹果的隐私保护归因框架。对未授权 ATT 的用户，在人群层面做聚合归因。

**SKAN 4.0 要点：**
- 最多 3 次回传（0–48 小时、3–7 天、8–35 天）
- 转化价值：64 级（0–63）
- 来源标识：最多 4 位（10,000 种组合）

**隐私阈值挑战：** 安装量不够时，转化价值回传为"null"。

| 平台 | 建议的日安装量 |
|---|---|
| Google Ads | 100+ / 天 |
| Facebook | 88+ / 天 |

> **注意：** 这是平台建议；苹果不公开阈值。所需量级因类目和广告系列组合而异。

### 9-3. iOS 运营最佳实践

| 规则 | 原因 |
|---|---|
| iOS 广告系列原则上保持 8 个左右或更少 | 防止信号碎片化（运营指引，不是平台上限） |
| 不用少于 2 天的数据做决策 | 模型化数据需要时间落地 |
| 优化 ATT 弹窗 | 授权率越高，数据质量越好 |
| 必须接入 Firebase SDK | iOS 端侧衡量的必需项 |
| 保持充足的安装量 | 为了越过 SKAN 阈值 |

### 9-4. iOS 实施检查清单

| 任务 | 说明 |
|---|---|
| SKAN 转化价值口径设计 | 决定哪个应用内事件映射到哪个转化价值（0–63）。按收入层级和互动阶段分类 |
| 考虑回传延迟的判断窗口 | SKAN 4.0 最长延迟 35 天。决策至少用 7 天滑动平均 |
| ATT 弹窗时机和文案优化 | 用户体验到应用价值之后再弹（例如教程完成后），授权率更高 |
| Firebase SDK 端侧衡量 | 满足 iOS 隐私要求的必需项 |
| 确认 MMP 侧的 SKAN 支持 | 检查 MMP（AppsFlyer、Adjust 等）的 SKAN 4.0 就绪度和配置 |

### 9-5. AdAttributionKit（AAK）迁移

苹果在 WWDC 2024 推出了 AdAttributionKit（AAK），是基于 SKAN 基础的新一代隐私保护归因框架。WWDC 2025 又加了 AAK 更新，包括重叠转化窗口支持和更多回传控制。MMP 和广告平台的支持还在变化中——定期检查最新状态。

## 10. 运营节奏与放量

### 10-1. 运营节奏

| 节奏 | 事项 |
|---|---|
| **每日** | 预算消耗进度、CPI / CPA 趋势、异常检查 |
| **每周** | 素材表现、广告效力、素材更新评估 |
| **双周** | 出价微调（±20% 以内）、测试新广告组 |
| **每月** | 全账户 ROI 复盘、结构审计、新广告系列评估 |

### 10-2. 放量策略

**放量前提：**
- CPA 稳定 5–7 天
- 每天 20–30+ 目标事件

**放量规则：**

| 规则 | 细节 |
|---|---|
| 每 48–72 小时最多加预算 20% | 突然大跳会破坏 AI 学习 |
| 每 24 小时最多调出价 20% | 大改动重置学习 |
| 改目标就建新广告系列 | 不建议原地把 tCPI 切成 tCPA |

### 10-3. 拿下 YouTube 流量

YouTube 覆盖量最大，但出价太低可能拿不到 YouTube 的投放。

**扩大 YouTube 覆盖的方法：**
- 始终上传高质量视频（横版 + 竖版）
- 逐步加价测试 YouTube 库存的获取
- 遵循 ABCD 框架

### 10-4. 联动应用商店优化（ASO）

应用广告系列用应用商店页面自动生成文案和创意。优化商店直接影响广告系列效果。

| ASO 元素 | 影响 |
|---|---|
| 应用标题 / 描述 | 被 AI 用作关键词信号 |
| 截图 | 自动生成视频的素材来源 |
| 预览视频 | 驱动商店页转化率 |
| 评分 / 评论 | 商店页的信任信号。低评分严重伤害转化率 |
| 下载量 | 起到社会认同作用 |

## 11. Web to App Connect

### 11-1. 概述

Web to App Connect 实现从网站广告系列（搜索、购物、P-MAX 等）到应用的无缝衔接。衡量网站广告系列带来的应用安装和应用内行为。

### 11-2. 支持的广告系列类型

| 广告系列类型 | 支持情况 |
|---|---|
| 搜索 | 支持 |
| 购物 | 支持 |
| Performance Max | 支持 |
| YouTube | 支持（2025 年扩展） |
| Demand Gen | 支持（2025 年扩展） |
| 酒店广告 | 支持（2025 年扩展） |

### 11-3. 核心功能

| 功能 | 说明 |
|---|---|
| 深度链接集成 | 网站广告点击 → 直接打开应用内对应页面 |
| 统一转化 | 自动合并应用和网站事件 |
| 网站到应用获客 | 衡量网站广告系列带来了多少应用安装 |
| 统一概览卡 | 网站和应用效果并排对比 |

### 11-4. 影响

Web to App Connect 能改善网站发现到应用转化的连贯性。在 iOS 上尤其能呈现网站广告系列对应用安装的贡献——这些贡献原本更难被看到。

## 12. 常见失败模式与应对

### 12-1. 广告系列设计失败

| 失败 | 问题 | 应对 |
|---|---|---|
| 同地域同目标跑多个广告系列 | 自我蚕食推高 CPI | 默认合并；只有理由充分才拆分 |
| 一个广告系列塞所有素材和所有地域 | 忽略语言和 LTV 差异；优化失败 | 按系统 / 地域 / 语言合理拆分 |
| iOS 广告系列太多 | 信号碎片化降低学习精度 | 原则上 8 个左右或更少；地域 / 语言 / 目标差异大时破例拆分 |

### 12-2. 预算 / 出价失败

| 失败 | 问题 | 应对 |
|---|---|---|
| 预算-出价比太低 | "预算受限"状态；学习不足 | 保持 tCPI × 50、tCPA × 10 的最低线 |
| 学习期频繁改出价 / 预算 | AI 学习重置；优化停滞 | 至少 1–2 周不动 |
| 单步放量 >20% | 学习失稳；CPA 冲高 | 每 48–72 小时 20% 阶梯 |
| 同一广告系列内 tCPI 切 tCPA | 丢失学习数据 | 切换就建新广告系列 |

### 12-3. 创意失败

| 失败 | 问题 | 应对 |
|---|---|---|
| 长期不更新创意 | 创意疲劳拖累效果 | 定期更新素材（每周 1–2 次指引内） |
| 一次换掉所有素材 | 没有对比基线；不知道什么有效 | 增量替换 |
| 没上传视频素材 | YouTube 投放受限 | 始终至少上传横版 + 竖版 |
| 图片里文字太多 | 可见性低、效果差 | 文字保持轻量（≤ 图片面积的 20–25%） |

### 12-4. 衡量失败

| 失败 | 问题 | 应对 |
|---|---|---|
| 转化事件选错 | 量级太低或业务价值太低 | 选每天 10+ 的事件。分步迁到深层事件 |
| iOS 用少于 2 天的数据做判断 | 模型化数据还没落地 | 至少用 3–5 天数据 |
| 没有 Firebase / MMP | 应用内行为测不到 | 上线前先搭好衡量基础 |

### 12-5. 运营失败

| 失败 | 问题 | 应对 |
|---|---|---|
| 应用商店页面放任不管 | 自动生成素材变差；转化率掉 | 定期优化商店信息（ASO） |
| 低评分还打广告 | 商店页流失更高 | 放量前先提升评分 |
| 多语言地区不做本地化 | 语言不匹配的用户转化差 | 按主要语言拆分 |
