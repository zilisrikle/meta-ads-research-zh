# Meta 广告搭建实施检查清单

当计划需要转化为实施检查清单时，使用本参考文档。战略、结构、Advantage+、衡量和创意决策归各自的专用参考文档；本文件仅覆盖搭建任务与上线前的质量检查（QA）。

## 1. 商户与广告账户搭建

1. 在 Meta 商户管理平台（Meta Business Suite / Business Manager）中确认商户组合（business portfolio）。
2. 连接 Facebook 公共主页与 Instagram 账户。
3. 确认广告账户的时区、货币、付款方式、业务用途与访问权限角色。
4. 确认网站类广告系列的域名所有权与落地页访问权限。
5. 确认商品目录（catalog）所有权以及产品/目录类广告系列所需的 Commerce Manager 访问权限。
6. 确认 App 所有权、App ID、应用商店链接、SDK/MMP 访问权限以及应用类广告系列的深度链接所有权。
7. 确认一键私信（click-to-message）广告系列所需的 WhatsApp 商户账户、Messenger 或 Instagram Direct 所有权。

## 2. 衡量搭建

1. 通过直接安装、GTM、合作伙伴集成或平台原生集成方式安装 Meta Pixel。
2. 当需要按转化优化时，在 Pixel 之外并行实施转化 API（Conversions API，CAPI）。
3. 为同一事件配置浏览器端/服务器端去重（deduplication），使用相同的事件名称与事件 ID（`event_id`）。
4. 对营收事件始终一致地发送价值（value）与货币（currency）。
5. 在允许范围内发送经用户同意的匹配参数：哈希邮箱、哈希电话、外部 ID（external ID）、`fbp`、`fbc`、IP 地址与用户代理（user agent）。
6. 放量前先检查事件管理工具（Events Manager）诊断、事件匹配质量（Event Match Quality，EMQ）、去重、事件延迟、价值/货币一致性与事件量。
7. 应用类广告系列确认 SDK 或 MMP 集成、App 事件、SKAN/AAK 要求，以及适用时的 App 事件转化 API（CAPI for App）。
8. CRM/线下转化项目确认线索/订单 ID、阶段映射、上传频次与后端对账。

## 3. 受众实施

| 受众类型 | 搭建检查 |
|---|---|
| 宽泛受众 | 仅限制真实约束，如地域、语言、年龄与合规；除非目标 playbook 另有要求，避免堆叠过窄的兴趣条件。 |
| 自定义受众（Custom Audience） | 基于网站、App、客户名单、互动、视频、即时表单（Instant Form）或 CRM 来源构建；确认规模与回溯窗口（retention window）。 |
| 排除（Exclusions） | 在当前界面与政策允许范围内，使用客户、已购用户、线索、员工、无效地域等硬性业务排除条件。 |
| Advantage+ 受众 | 除非界面明确标记为控制项，否则将纳入条件视为建议（suggestions）；在当前界面中核实硬性控制项。 |
| 特殊广告类别（Special Ad Categories） | 构建受众或表单前先查阅 `policy-and-special-categories.md`。 |

## 4. 广告系列与广告搭建 QA

| 领域 | 检查项 |
|---|---|
| 广告目标（Objective） | 与业务结果及所选 playbook 一致。 |
| 转化位置（Conversion location） | 网站、App、即时表单、来电、私信、目录或线下路径正确。 |
| 表现目标（Performance goal） | 使用量充足、延迟可接受的最深层可靠事件。 |
| 预算 | 能支撑预期学习量，且不碎片化信号。 |
| 竞价策略 | 从实际观察到的经济效益出发；在量稳定前不使用严格目标。 |
| 版位 | 默认使用 Advantage+ 版位，除非有证据或政策要求排除。 |
| 创意 | 已加载足够多差异化的概念与适配版位的素材。 |
| 落地页 | 落地页、表单、商店页、目录、结账页或私信流程与广告承诺一致。 |
| 追踪 | Pixel/CAPI/App/CRM 事件触发一次、去重正确、传递所需值。 |
| 政策 | 类别、声明用语、表单字段、免责声明与落地页通过审核风险检查。 |

## 5. 广告搭建细节

- 预算允许时，每波测试起步使用 3–5 个差异化创意概念。
- 仅当每种格式有明确角色时，才混用图片、视频、轮播、目录主导和表单/私信格式。
- 按版位调整宽高比与构图，而不是依赖自动裁剪。
- 仅在审核品牌契合度、文字叠加、产品边缘与受管类别风险后，才使用 Advantage+ 创意。
- 当存在多个兼容素材且能监控输出质量时，使用灵活广告格式（Flexible Ad Format）。

| 元素 | 建议长度 | 数量 |
|---|---:|---:|
| 主文案（Primary text） | 125 个字符以内为宜，超过可能被截断 | 3–5 个版本 |
| 标题（Headline） | 27 个字符以内为宜，超过可能被截断 | 3–5 个版本 |
| 描述（Description） | 通常 25–30 个字符；并非所有版位都显示 | 1–3 个版本 |
| 行动号召（CTA） | 从 Meta 预设按钮中选择 | 1 |

## 6. 上线 QA

发布前，逐项核实：

1. 命名遵循账户命名规范。
2. 广告系列/广告组/广告的状态正确。
3. 预算与排期符合预期。
4. 归因设置已记录。
5. 已应用必需的排除与特殊广告类别设置。
6. 表单隐私政策、免责声明、webhook/CRM 路由与线索送达正常工作。
7. 目录商品有售、有库存、定价正确，且与事件的内容 ID（content ID）匹配。
8. 应用类广告系列已配置深度链接、商店链接、App 事件及 MMP/SKAN/AAK 要求。
9. 测试事件（Test Events）或等效诊断确认转化路径通畅。
10. 上线前已写好第一周监控计划。
