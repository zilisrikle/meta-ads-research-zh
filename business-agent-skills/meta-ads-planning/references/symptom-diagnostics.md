# 基于症状的诊断

本参考用于已有账户的改进工作。先诊断失败模式，再提修改建议。多数 Meta 广告问题源于信号质量差、创意弱、落地页差、结构碎片化、经济目标不现实，或过度信任归因数据。

## 第一轮分诊

| 检查项 | 如果出问题 | 优先级 |
|---|---|---|
| 衡量 | Pixel/CAPI 缺失、事件重复、主事件错误、去重差 | 在改出价或结构之前先修 |
| 转化质量 | 原始线索、低毛利订单、浅层 App 事件占主导 | 重设事件/价值回传 |
| 创意 | 钩子/CTR 弱、疲劳、素材高度雷同、证明/卖点弱 | 先于出价调整刷新概念 |
| 落地页 | 落地页/表单/结账页/商店页与广告不匹配或阻力大 | 放量前先修落地页 |
| 结构 | 广告系列/广告组过多、预算过小、受众重叠 | 围绕干净信号合并 |
| 经济 | 目标 CPA/ROAS 无法实现 | 重置目标、卖点、利润率或预算 |
| 归因 | 再营销/浏览归因/老客让 ROAS 虚高 | 拆开报告并测试增量 |

---

## 花费高、转化少

```
Spend high, conversions low
├── 追踪坏了？
│   └── 检查 Pixel/CAPI、去重、事件触发、价值/货币
├── 优化事件选错了？
│   └── 用量充足的最深层可靠事件
├── 创意吸引眼球但不吸引购买意愿？
│   └── 重做卖点、证明、资格筛选，以及信息与落地页的一致性
├── 落地页弱？
│   └── 修落地页、表单、结账页、商店页、速度、信任、定价
├── 受众太窄或太碎？
│   └── 在业务约束允许范围内合并与放宽
└── 预算相对于 CPA 太小？
    └── 收紧结构或用已验证的代理事件（proxy event）
```

---

## 线索便宜、质量差

```
Leads cheap, quality low
├── 即时表单摩擦太小？
│   └── 用高意向（Higher Intent）表单类型并增加资格筛选问题
├── 卖点吸引了不匹配的用户？
│   └── 增加价格、匹配度、服务区域、角色或意愿筛选条件
├── 在优化原始线索？
│   └── 回传 MQL/SQL/商机事件或使用 CRM 反馈
├── 版位质量问题？
│   └── 检查版位/流量源质量；必要时测试排除 Audience Network
├── 销售跟进太慢？
│   └── 审计首响速度（speed-to-lead）、分发路由与 CRM 状态
└── 宽泛投放在找便宜的流量洼地？
    └── 加业务约束，用创意做更精准的资格筛选
```

## CTR 高、CPA 也高

| 原因 | 如何识别 | 行动 |
|---|---|---|
| 标题党钩子 | CTR 高、落地页 CVR 差、停留时间短 | 让钩子筛选意愿，而不只是猎奇 |
| 卖点错位 | 用户点击但不转化 | 对齐广告承诺、落地页标题、价格、证明、CTA |
| 事件选错 | 浅层行为多、购买/线索少 | 量允许时把主事件往深层移 |
| 信任不足 | 在购买/填表环节流失 | 加评价、保障、资质、演示 |
| 受众错位 | 低匹配用户的互动 | 收紧创意的资格筛选或控制项 |

不要孤立地优化 CTR。CTR 更高可能吸引低匹配用户，反而推高 CPA。

---

## CPM 或频次上涨

| 原因 | 如何识别 | 行动 |
|---|---|---|
| 创意疲劳 | 频次上升、CTR 下降、CPA 上升 | 上真正意义上的新概念 |
| 受众饱和 | 受众小、频次高、触达受限 | 放宽、合并，或给再营销设上限 |
| 竞价压力 | 新鲜创意 CPM 也涨 | 检查季节性、竞争、卖点、预算节奏 |
| 加预算暴露了素材库太薄 | 放量后 CPA 上涨 | 加创意深度或放慢加预算节奏 |
| 再营销过度曝光 | 温流量频次高、ROAS 里浏览归因占比高 | 限预算、换信息、做对照测试（holdout） |

## 学习受限或投放不稳定

```
Learning limited / unstable
├── 预算 ÷ CPA 买不到足够事件？
│   └── 合并或加预算
├── 广告系列/广告组太多？
│   └── 按目标、地域、业务逻辑合并
├── 事件相对于当前量太深？
│   └── 临时用已验证的代理事件
├── 最近改动太多？
│   └── 停手；等稳定窗口过去
├── 创意库太薄？
│   └── 加差异化概念，不是微小变体
└── 出价/控制太严？
    └── 稳定前用最高量（Highest volume）
```

---

## Advantage+ Sales 的 ROAS 很高，业务营收没动

```
ASC ROAS high, business revenue flat
├── 老客占比高？
│   └── 看受众/客户拆解和客户定义
├── 再营销或温流量池偏置？
│   └── 对比冷启动/新客指标，条件允许时做对照组
├── 浏览归因（view-through）占比高？
│   └── 点击归因和浏览归因分开报告
├── 低毛利商品占主导？
│   └── 用商品集、价值规则或利润口径报告
├── 目录/商品流问题？
│   └── 检查上架状态、价格、商品组合、创意覆盖
└── 没有增量证据？
    └── 用地域/客户对照组、转化提升（conversion lift）或财务对账
```

---

## 创意测试跑不出明显赢家

| 原因 | 诊断 | 行动 |
|---|---|---|
| 变体太像 | 钩子/视觉/卖点重复 | 测试不同概念 |
| 预算撑不起的广告太多 | 很多广告拿不到展示 | 缩小测试规模 |
| 判读太早 | 转化太少或转化延迟 | 拉长窗口 |
| KPI 错了 | 在优化钩子/CTR，但 CPA 才是关键 | 把判读锚定到漏斗阶段 |
| 广告系列结构偏置了投放 | 某条广告凭运气先拿到花费 | 仅在预算支持时用受控测试结构 |

---

## 诊断输出格式

诊断账户时，返回：

1. 按置信度排序的可能根本原因。
2. 确认或排除每个原因所需的证据。
3. 现在就要做的改动。
4. 数据到来前不要做的改动。
5. 预期的稳定窗口。
