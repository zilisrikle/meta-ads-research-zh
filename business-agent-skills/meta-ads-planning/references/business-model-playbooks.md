# 业务模式 playbook

在选择 Meta 广告目标或结构之前，先用本参考确认。业务模式、销售方式、利润率、转化延迟和创意供给，决定了「好」的 Meta 架构长什么样。

## 选择原则

| 业务模式 | 先问 | 默认倾向 | 主要风险 |
|---|---|---|---|
| 电商 / D2C | 购买/价值追踪和目录数据是否可靠？ | Sales 广告系列 + 宽泛/Advantage+ 投放，外加创意测试 | 平台 ROAS 掩盖利润率或老客偏置 |
| B2B 线索型 | 合格线索或商机回传能否送回来？ | Leads/Sales + 质量闭环，不追原始 CPL | 优化到便宜的无效线索 |
| SaaS / 订阅 | 哪个事件能预测激活、付费转化或留存？ | Leads/Sales 从试用/注册往价值事件走 | 优化到不激活的试用 |
| 本地服务 | 服务区域、排班、预约/来电承接、本地证明是否清楚？ | Leads/Sales + 必要时配本地认知 | 为跨区或低意愿线索付费 |
| App | 哪个应用内事件能预测留存价值？ | App 推广，分阶段加深事件 | 永远在优化安装 |
| 品牌 / 认知 | 什么提升或下游行为能证明价值？ | Awareness/视频 + 衡量计划 | 把触达或视频播放当业务结果 |

## 电商 / D2C

### 适配的广告系列组合

| 阶段 | 广告系列 | 角色 |
|---|---|---|
| 上线 | 手动 Sales，或就绪后用 Advantage+ Sales | 建立购买/价值信号与创意基线 |
| 稳定期 | Sales 放量 + 创意测试 | 放大验证过的创意，持续喂新概念 |
| 规模化 | Advantage+/手动 Sales，外加目录/商品集逻辑 | 扩大投放，同时监控新老客与利润率 |

### 转化设计

| 信号 | 用法 |
|---|---|
| 带价值的 Purchase | 主力基线 |
| 利润口径或贡献毛利口径价值 | 毛利率、折扣、运费、退货率差异大时更优 |
| AddToCart / InitiateCheckout | 仅当购买太稀疏且代理事件能预测购买时，作临时代理 |
| 新客 / 老客分群 | 用于报告与预算控制输入，不一定是优化事件 |

### 设计要点

- 当转化追踪、产品市场契合度、预算、创意多样性都强时，Advantage+ Sales 可以跑得很好。
- 用新客占比、增量和业务营收来验证 Advantage+ Sales，不要只看平台 ROAS。
- 如果存在收割老客的风险，定义客户/互动客户受众，在当前界面支持的情况下考虑手动 Sales 结构或排除。
- 商品流（feed）质量很重要：名称、图片、上架状态、价格、商品集、利润标签、促销状态、库存都要能支撑决策。
- 目录主导格式和静态/视频概念要互相测试；不要默认动态/目录广告一定赢。

## B2B 线索型

### 适配的广告系列组合

| 阶段 | 广告系列 | 角色 |
|---|---|---|
| 上线 | Leads 或 Sales，转化质量定义要紧 | 建立线索量与质量基线 |
| 稳定期 | 线索获取 + 教育/再营销 | 用视频/证明培育长周期买家 |
| 规模化 | CRM 反馈可用后再放宽拓客 | 先控住便宜线索陷阱再扩张 |

### 转化设计

| 信号 | 用法 |
|---|---|
| 原始即时表单线索 | 只有在质量和跟进都稳定时才作主事件 |
| 高意向（Higher Intent）即时表单线索 | 线索价值值得增加摩擦时更好 |
| 网站线索 / 演示预约 | 意愿通常更高，量更小 |
| 合格线索 / MQL / SQL / 商机 | 回传量和延迟可接受时首选 |

### 设计要点

- 便宜的 CPL 不是目标。监控合格线索率、商机率、成交率、首响速度和销售反馈。
- 用资格筛选问题、价格/匹配度提示和清晰文案，把不匹配的线索挡在外面。
- 即时表单和网站转化路径要对比测试；移动端阻力与线索质量常此消彼长。
- 当线索质量难验证时，Audience Network 或过宽的版位可能需要复核。
- 预算小就先围绕一个干净的线索质量闭环合并，暂不上认知或再营销。

## SaaS / 订阅

### 适配的广告系列组合

| 阶段 | 广告系列 | 角色 |
|---|---|---|
| 上线 | Leads/Sales 做注册、演示或试用 | 先证明获客信号成立 |
| 稳定期 | 转化广告系列 + 证明/教育创意 | 提高试用或演示质量 |
| 规模化 | 量支持时做价值感知优化 | 往订阅、留存用户或 LTV 信号走 |

### 转化设计

| 信号 | 用法 |
|---|---|
| 注册 / 免费试用 | 激活质量被监控时，是有用的早期信号 |
| 演示预约 | 销售主导型 SaaS 在有资格筛选时不错 |
| 激活试用 / 产品合格线索（PQL） | 比原始注册更好的预测指标 |
| 订阅 / 留存价值 | 业务真相，但可能稀疏或延迟 |

### 设计要点

- 自助试用和销售主导演示的经济效益不同就分开算。
- 创意要讲清问题、展示产品、给出信任证明、处理切换异议。
- 不要优化到低意愿的内容下载，除非它能预测商机。
- 尽量把 CRM/产品激活反馈回传给 Meta。

## 本地服务 / 本地商户

### 适配的广告系列组合

| 阶段 | 广告系列 | 角色 |
|---|---|---|
| 上线 | Leads/Sales，或 Awareness + Leads | 抓住本地需求、建立证明 |
| 稳定期 | 本地转化 + 再营销 | 重新触达网站访客和历史互动者 |
| 规模化 | Awareness/视频 + 转化广告系列 | 直接需求有限时做本地熟悉度 |

### 转化设计

| 信号 | 用法 |
|---|---|
| 预约 / 排期 | 可追踪时首选 |
| 合格来电 | 来电承接强时作主事件 |
| 线索表单 | 质量可复核时作主事件 |
| 门店销售 / POS / 已预约工单 | 业务真相 |

### 设计要点

- 地域约束是真实的业务控制项，不要让宽泛投放跨过服务边界。
- 本地证明很重要：评价、附近案例、团队可信度、前后对比、门店或服务区域清晰度。
- 广告排期要和来电承接对齐。漏接电话是运营失败，看起来却像广告跑得差。
- 只有在复购/补货不是目标时才排除老客。

## App

### 适配的广告系列组合

| 阶段 | 广告系列 | 角色 |
|---|---|---|
| 上线 | App 推广，优化安装 | 建立安装与事件基线 |
| 稳定期 | App 推广，优化应用内事件 | 量支持后往质量走 |
| 规模化 | 价值优化 / ROAS（可用时） | 往营收或留存价值优化 |

### 转化设计

| 信号 | 用法 |
|---|---|
| 安装 | 仅作早期量信号 |
| 注册 / 新手引导完成 / 关键行为 | 能预测留存时作代理 |
| 购买 / 订阅 / 留存价值 | 量稳定后首选 |

### 设计要点

- 随信号成熟，把优化事件从安装逐级加深到价值。
- iOS/Android 在衡量、经济效益或事件量差异大时拆分。
- 创意要快速展示 App 体验；用动效和证明，不只放应用商店截图。
- 再营销要带增量怀疑：回流用户可能本来就会自然回来。

## 品牌 / 认知

### 适配的广告系列组合

| 阶段 | 广告系列 | 角色 |
|---|---|---|
| 上线 | Awareness 或 Engagement 视频 | 建立触达、记忆和温流量池 |
| 稳定期 | Awareness + 转化承接 | 把需求创造接到下游行为 |
| 规模化 | 全漏斗结构 | 用提升度（lift）、搜索提升、直接流量或混合指标验证 |

### 转化设计

| 信号 | 用法 |
|---|---|
| 触达 / 频次 | 投放控制，不是业务真相 |
| ThruPlay / 视频播放 | 创意互动与温流量池建设 |
| 品牌提升 / 转化提升 | 有条件时首选 |
| 搜索/直接/网站流量提升 | 有用的交叉验证 |

### 设计要点

- 认知类广告系列需要创意和衡量纪律，没有任务就别上"便宜触达"。
- 视频钩子、差异化资产、品类切入点和证明，比精细的受众切分更重要。
- 频次目标看场景；盯着疲劳、CTR、记忆度和下游行为。

## 多广告系列组合模式

以下模式是起点。根据预算充足度、转化量、衡量质量、创意供给和增量风险调整。

### 创意测试 + 放量

```
Creative Test Campaign       <- 受控的概念发现
Sales/Leads Scaling Campaign <- 验证过的概念 + 更宽的投放
```

只有预算撑得起时才单独建测试广告系列。小账户通常需要一个合并广告系列，测试和放量一起做。

### 带客户控制的电商获客

```
Sales 或 Advantage+ Sales     <- 主购买引擎
Manual Sales Prospecting      <- 必要时用更严的客户排除
Remarketing / CRM campaign    <- 只有在信息或预算控制需要时才建
```

监控新客与老客的贡献。如果平台 ROAS 好看但业务营收没动，诊断老客收割和浏览归因虚高。

### 线索质量闭环

```
Lead Capture Campaign         <- 即时表单或网站线索
Education / Proof Campaign    <- 视频、证言、异议处理
CRM Feedback Loop             <- 合格线索 / 商机事件回传
```

合格线索率和跟进没达标前，不要放量原始线索。

### App 分阶段优化

```
Install Campaign              <- 早期事件量
In-App Event Campaign         <- 质量代理
Value / ROAS Campaign         <- 量支持后做变现
```

当安装优化不再预测留存价值时，关掉或升级它。
