# Meta 账户数据诊断

当用户提供 Meta 广告账户数据以寻求改进时，使用这份参考文档：CSV/XLSX 导出、复制的表格、截图、仪表盘、Ads Manager 细分数据、Events Manager 诊断、商品目录（Catalog）报告、CRM/POS 导出、应用/MMP 报告、API 提取，或一份指标的文字总结。诊断的任务是识别：数据能证明什么、不能证明什么，以及哪些账户改动应优先。

## 操作规则

- 从业务结果倒推诊断：先看收入、合格商机管道、留存的应用用户、预约工单、门店/POS 销售额或边际贡献，再看平台的每次转化费用/广告投入回报率（CPA/ROAS）。
- 把信号质量和流量质量分开看。糟糕的优化事件会让好流量看起来差，也会让差流量看起来好。
- 不要只信 Meta 一家。有条件时，把 Ads Manager 与 Events Manager、后端订单、CRM/POS、应用分析/MMP、商品目录诊断和财务数据对账。
- 用花费加权的证据。一个每次转化费用很差的小广告组，远不如一个吃掉 35% 花费但合格结果很弱的广告系列紧急。
- 当决策重要时，拆分点击转化（click-through）、互动转化（engage-through）、浏览转化（VTC, View-Through Conversion）、模型估算、新增客户与既有客户的贡献。
- 避免同时改出价、预算、目标、转化事件、创意和结构。数据应该产出一份有序的行动计划，而不是一堆改动。
- 把截图和总结当作方向性参考。只有当决策依赖于细分、关联或精确总数时，才要求提供原始行数据。

## 1. 数据接入与数据质量检查

在分析效果之前，先明确数据集及其局限。

| 检查项 | 检查内容 | 为什么重要 |
|---|---|---|
| 数据来源 | Ads Manager、Events Manager、CRM、Shopify/后端、POS、商品目录、应用/MMP、WhatsApp/Messenger、Looker | 决定归因、日期逻辑和可用的关联方式 |
| 日期口径 | 展示日期、点击日期、转化日期、事件时间、上传时间、成交日期 | 日期口径不一致是很多差异的原因 |
| 日期范围 | 过去 7/14/30/60/90 天、季节性、转化延迟覆盖 | 短窗口会对噪声过度反应；长窗口会掩盖近期变化 |
| 时区/币种 | 广告账户时区、CRM 时区、后端时区、本地币种 | 影响按日关联、每次转化费用/广告投入回报率、花费节奏和收入 |
| 筛选条件 | 广告系列状态、目标、转化位置、归因设置、版位、地域、年龄、设备 | 隐藏的筛选条件会让数据不具代表性 |
| 归因 | 7 天点击、1 天点击、1 天浏览、1 天互动转化、模型估算、MMP/SKAN/AAK | 决定各来源总数是否应该对得上 |
| 转化定义 | 优化事件、标准/自定义事件、原始潜在客户 vs 合格潜在客户、应用事件、价值 | 定义投放系统在向什么学习 |
| 行粒度 | 账户、广告系列、广告组、广告、创意、版位、事件、产品、潜在客户、用户、订单 | 决定能做哪些决策 |

如果数据不完整，仍然给出诊断，但要加上**数据局限**章节，并把"有依据的发现"和"待确认事项"分开。

## 3. 诊断顺序

按顺序执行。如果账户正在向错误的事件优化，不要从裁剪创意开始。

### A. 衡量与对账

| 数据信号 | 可能含义 | 行动 |
|---|---|---|
| Meta 转化高、后端收入持平 | 收割既有客户、浏览转化/互动转化虚增、重复/误触发事件、归因重叠 | 拆分归因/客户类型；对账订单 ID；测试增量 |
| 转化数等于或接近点击数/落地页浏览数 | 标签很可能在页面加载时或错误触发器上触发 | 改出价前先审计 Pixel/CAPI 事件触发 |
| 浏览器端与服务端事件都高且有去重警告 | 去重失败 | 对齐事件名称与 `event_id`；核验事件时间与来源 |
| CAPI 事件延迟 | 服务端延迟可能削弱优化与报告 | 修复排队机制，尽量接近实时发送 |
| 购买价值缺失或不一致 | 广告投入回报率/价值优化不可靠 | 修复价值/币种语义并记录定义 |
| CRM 合格潜在客户远低于原始潜在客户 | 投放系统在学习便宜的原始潜客 | 增加表单摩擦、导入合格阶段，或在条件成熟时使用转化型潜在客户（Conversion Leads） |
| Meta 与 MMP 的应用安装数差异显著 | SKAN/AAK/模型估算/日期口径/归因不一致 | 先比较归因口径，再断言某一方错误 |

### B. 预算、量级与学习可行性

| 数据信号 | 可能含义 | 行动 |
|---|---|---|
| 广告组远低于实际学习量级 | 投放决策很脆弱 | 合并、提高预算，或选择已验证的更大量级事件 |
| 日预算低于目标每次转化费用 | 学习会又慢又吵 | 收窄结构、提高预算，或仅在经济模型允许时降低目标 |
| 花费分散在很多低量级广告组 | 学习被打碎 | 围绕目标/经济模型/地域/合规合并 |
| 单结果成本目标/广告投入回报率目标花不出去 | 目标太紧或信号太弱 | 放松目标、回到最高量级，或先修信号再强行控制 |
| 再营销（Retargeting）消耗大量预算且广告投入回报率高 | 增量风险 | 设上限/做对照组/把预算转给拉新，并衡量混合结果 |

### C. 目标与流量质量

| 数据信号 | 可能含义 | 行动 |
|---|---|---|
| 流量广告系列点击便宜但没有购买 | 目标错配 | 收入用销售（Sales）目标；流量（Traffic）目标只用于内容/种草，并用落地页浏览质量 KPI 考核 |
| 互动广告系列点赞多但没有商机 | 社会证明不是转化信号 | 只做上/中漏斗辅助；建交接受众或切换到潜客/销售目标 |
| 潜客广告系列每次潜在客户费用便宜但成交率差 | 表单太容易、受众太宽、信息错位、跟进弱 | 用高意向（Higher Intent）表单、加筛选问题、CRM 反馈、修复首响速度 |
| 应用广告系列每次安装成本低但留存差 | 安装事件太浅 | 向应用内事件/价值升级，并诊断商店/应用内引导 |

### D. 创意与疲劳

| 数据信号 | 可能含义 | 行动 |
|---|---|---|
| 频次上升、点击率下降、每次转化费用上升 | 创意疲劳 | 上线新概念；不要只调预算/出价 |
| 很多在投广告没有花费 | 相似广告太多或预算不足 | 缩减在投集合，提高概念多样性 |
| 多条广告的质量/转化排名弱 | 优惠/信息/落地页错位 | 重建钩子、证明、筛选，以及落地页（Landing Page, LP）/表单的对齐 |
| Reels/Stories 有花费但视频留存差 | 前几秒或竖版适配弱 | 围绕钩子、产品、字幕、安全区重做 9:16 创意 |

### E. 落地页与运营

| 数据信号 | 可能含义 | 行动 |
|---|---|---|
| 落地页浏览高、转化率低 | 落地页/结账/表单问题 | 审计移动端速度、优惠匹配、证明、摩擦、追踪 |
| 即时表单（Instant Form）完成率高、联系率低 | 意向低、虚假/错误数据、跟进慢 | 高意向表单、自定义问题、验证、CRM 首响速度 |
| 点击发消息量大、合格对话少 | 机器人/欢迎流程或转人工质量问题 | 加筛选型快捷回复、人工 SLA、营业时间逻辑 |
| 目录广告（Catalog ads）效果不达标 | Feed 准入/匹配/产品集问题 | 修复诊断、内容 ID、可用性、图片、标签 |

### F. 增量与归因

| 数据信号 | 可能含义 | 行动 |
|---|---|---|
| 平台广告投入回报率高、混合收入持平 | 归因收割、再营销、既有客户集中 | 新/既有客户拆分、后端对账、对照组 |
| 浏览转化或互动转化主导转化 | 非点击归因可能夸大因果效应 | 分开报告点击/互动/浏览，重要时做提升测试 |
| Advantage+ 销售广告系列放大既有客户 | 客户控制或排除不足 | 定义客户名单，用预算上限/控制（如有），或手动拆分 |
| 再互动应用广告系列在没有对照组时看起来很强 | 很多用户本来就会回来 | 用增量/对照组和留存价值衡量，不只看重开 |

## 4. 按报告类型的阅读指引

| 数据产物 | 先问的问题 | 能支持的决策 |
|---|---|---|
| 广告系列表格 | 花费集中在哪里？哪些目标有像样的事件量级？ | 预算转移、目标修正、合并 |
| 广告组表格 | 哪些广告组受学习限制、重复、过窄或预算不足？ | 合并、受众控制、预算策略 |
| 广告/创意报告 | 哪些概念在驱动花费和合格结果？能看到疲劳吗？ | 创意更新、概念扩展、广告裁剪 |
| 归因细分 | 点击/互动/浏览各占多少？定义变过吗？ | 报告口径、增量需求、财务对账 |
| 版位细分 | 便宜版位产出了质量结果吗？ | 版位控制、创意适配、质量诊断 |
| Events Manager 诊断 | 事件是否重复、缺参数、延迟或匹配度低？ | 先修追踪，再动媒体 |
| 商品目录诊断 | 哪些产品无法投放或匹配事件？ | 修 Feed、产品集策略、目录广告系列诊断 |
| CRM 导出 | 哪些广告系列/表单产出合格潜客、商机、收入或垃圾？ | 导入合格潜客、表单设计、预算再分配 |
| 应用/MMP 报告 | 哪些安装能留存或变现？SKAN/AAK 有何不同？ | 事件深度升级、iOS/Android 拆分、再互动测试 |
| 变更历史 | 预算、出价、事件、创意或结构修改后，效果变了吗？ | 稳定期窗口与回滚/暂停决策 |

## 5. 优先级模型

用这个评分给发现排序。优先修复高花费、高业务影响、高证据置信度、低学习风险的问题。

| 因素 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 花费影响 | 小尾巴 | 明显 | 头部花费驱动 |
| 业务影响 | 表面指标 | 每次转化费用/广告投入回报率变动 | 收入、商机、毛利、追踪完整性 |
| 证据置信度 | 一张截图/轶事 | 分段的平台数据 | 跨来源对账 |
| 修复成本 | 多团队项目 | 需要一定实施 | 账户/Feed/文案即时改动 |
| 学习风险 | 重置主要学习 | 中等 | 低风险护栏或衡量修复 |

把这个公式当作指引，而不是硬性评分：

```
Priority = (Spend impact + Business impact + Evidence confidence + Fix ease) - Learning risk
```

默认按这个顺序修复：

1. 衡量完整性：重复/缺失事件、事件语义、CAPI 去重、CRM 关联、目录匹配。
2. 目标/事件修正：销售 vs 流量、潜客 vs 互动、原始潜客 vs 合格潜客、安装 vs 应用价值。
3. 浪费控制：客户排除/上限、弱版位、无效地域、被拒/缺货产品、明显低质的潜客路径。
4. 预算再分配：把花费从弱质量洼地转移到已验证的高意向/高毛利/高质量人群。
5. 落地页与创意：落地页、结账、表单、消息流程、应用商店、目录 Feed、概念质量。
6. 出价与结构：出价策略、目标、广告系列拆分/合并、Advantage+ vs 手动。
7. 增量测试：再营销、既有客户、浏览转化主导、Advantage+ 销售、应用再互动。

## 6. 数据驱动诊断的输出格式

当用户提供账户数据时，返回：

1. **已审阅数据**——来源、日期范围、行粒度、筛选条件、归因与局限。
2. **数据质量标记**——缺失字段、日期/归因不一致、可疑总数、不完整关联。
3. **主要诊断**——3-7 条有证据的排序发现。
4. **决策表**——改什么、为什么、预期效果、稳定期窗口，以及不能同时改什么。
5. **需要补充的数据**——只索要会改变决策的数据。

示例发现格式：

| 优先级 | 证据 | 解读 | 行动 | 避免 |
|---|---|---|---|---|
| P1：潜客质量导入 | Meta 显示 420 个原始潜客，CRM 显示 28 个 SQL 和 3 个商机；弱 SQL 集中在一个表单和一个版位 | 出价系统在学习便宜的表单填写，而不是合格商机 | 加高意向/筛选问题，同步合格阶段，把预算转给更好的表单/广告组 | 不要基于原始每次潜在客户费用加预算 |
| P2：去重失败 | Events Manager 显示购买去重警告，Pixel+CAPI 数量都在涨 | 购买总数可能虚增，学习不稳定 | 修复共用的 `event_id`、事件名称和事件时间 | 追踪修好之前不要改出价策略 |
| P3：既有客户集中 | Advantage+ 销售广告系列的广告投入回报率高，但后端新客收入持平 | 广告系列可能在收割既有需求 | 定义客户名单，检查新/既有拆分，用上限/排除（如有），做对照组测试 | 不要把平台广告投入回报率当作获客广告投入回报率报告 |

## 7. 易变项检查

在把这些写死进建议之前，先核验当前 Ads Manager/API 的行为：

- 归因列，以及用户的报告体系是否暴露了点击转化、互动转化和浏览转化。
- Advantage+ 销售广告系列的控制项、既有客户预算上限行为、导入广告和多广告组限制。
- Advantage+ 潜客广告系列的准入资格和默认开启行为。
- 详细定向（Detailed Targeting）排除和受众控制的可用性。
- AEM 网页/应用的 UI 行为和应用归因要求。
- Threads、Audience Network、WhatsApp、Marketplace、Shops，以及按目标/地域的版位可用性。
- 青少年定向、特殊广告类别（Special Ad Category）和区域政策限制。
