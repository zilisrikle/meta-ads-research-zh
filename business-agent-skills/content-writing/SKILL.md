# 内容写作

针对手头的目标写出最有效的文案，或诊断并重写已有文案。用户提供写作目的、受众、目标和原始素材。如果缺少重要信息，先询问或做调研，再开始写作。

## 第一性原理（First principles）

**写作归根结底是两件事：决定纳入哪些信息，以及决定如何表达。**无论是写一句话的标题，还是写三十页的报告，都一样。

0. **明确你想引发的改变**——说清楚读者读完之后应该处于什么状态。如果这一点模糊，后续的所有判断都会漂移。
   - **行动（Action）**——购买、注册、咨询、下载、回复。
   - **信服（Conviction）**——他们信任论证，得出“这适合我”的结论。
   - **兴趣（Interest）**——他们想继续读、继续了解、点击深入。
   - **持续阅读（Sustained reading）**——他们保持专注，读到最后也不跳出。
   - **消除疑虑（Removed objections）**——在读者提出之前，先解决常见阻碍（“太贵”“实际没效果”“时机不对”“不适合我这种人”）。
   - **理解（Understanding）**——他们带着对主题准确、完整的认知模型离开。
1. **收集（Gather）**——把关于主题、受众和背景的一切有用信息汇集起来。如果原始素材太薄，先询问或做调研，再动笔。
2. **筛选（Select）**——从收集到的内容中，只保留服务于你想引发的改变的部分。想把一切都说，等于什么都没说。对照读者的兴趣、问题和决策标准进行过滤。
3. **表达（Express）**——把筛选出的信息，放进最能打动这位读者的措辞、顺序和结构。同样的事实，形状不同，效果不同。
4. **用占位符，绝不编造**——当你没有具体的数字、客户名、引言、结果或细节时，不要用听起来合理的编造或含糊其辞来掩盖缺口。放入带标签的占位符（`[X% improvement]`、`[Customer name]`、`[Specific feature]`、`[Date]`），并向用户索要真实数据。一个编造的细节对可信度的伤害，超过十个可见的缺口。占位符是诚实的；用“显著提升”代替未知数字则不是。

大多数薄弱的写作败在第 1 步或第 2 步——原始素材不够，或没有“留下什么、删掉什么”的编辑纪律。表层的文字功夫救不了一篇根基就不聚焦的稿子。

## 工作流：写新东西

### 1. 锁定目标和简报

动笔之前，先搞清楚到底在写什么。

**先从上往下收窄交付物：**

- **模式（Mode）**——说服型（persuasive，改变行为或信念）还是信息型（informational，传递知识）？一篇稿子可以在小节层面混合两种模式，但主导模式决定之后的所有选择。
- **文体（Piece type）**——落地页、广告、邮件、社交媒体帖子、博客文章、提案、新闻稿、案例研究、内部文档、报告等。
- **格式约束（Format constraints）**——篇幅、渠道、语言，以及任何刚性结构要求（主题行字符限制、幻灯片页数、简报字数）。

**然后确认简报。至少包括：**

- **读者（Reader）**——他们的角色、脑子里的问题、已知什么、对什么存疑。能把他们描述得越具体，稿子打得越狠。
- **终态（End state）**——读者读完之后应处于的行动、信服、兴趣或理解状态（见“第一性原理”第 0 步）。终态模糊 → 稿子模糊。
- **分发上下文（Distribution context）**——他们从哪里来（广告、搜索结果、邮件、内部转发、直接发送），之前刚接触过什么，读完之后预期做什么。
- **语气约束（Voice constraints）**——品牌语气、风格指南、禁用/优先术语，或应当对齐的既有文案。已有成熟语气时再发明一套新语气，只会制造不一致。
- **手头素材（Source material on hand）**——稿子要立足的数字、客户案例、引言、论据、证据，我们有吗？还是需要先收集？没有素材就动笔，是走向编造或含糊其辞最稳的路。
- **反目标（Anti-goals）**——要避开的话题、监管或法律约束、过往争议、受众敏感点。提前说出来，比返工一稿容易。

如果有实质性信息不清楚，就问。用项目里已有的信息，别反复问用户。**不要一口气问完问题就直接开写——等拿到答案再往下走。**

**问多少的经验法则：**

| 简报 | 问多少 |
|---|---|
| “收紧这个 CTA”/“让这个主视觉标题更有力” | 最少——就着现有的写 |
| “给这个落地页想三个备选标题” | 轻量——确认角度，不用确认整个简报 |
| “根据这次客户访谈写一篇案例研究” | 适中——先导问题和结果选哪个、目标读者是谁 |
| “新功能上线公告邮件” | 大量——受众分群、到底上了什么、品牌语气、过往上线 |
| “写一篇关于 [主题] 的博客” | 非常多——受众、角度、搜索意图、篇幅、语气、分发渠道 |
| “给新产品写首页文案” | 非常多——动笔前做完整的需求采集 |

交付物越新、越大、越模糊，问得越多。在已有稿子里做小调整和跟进时，少问。

### 2. 收集原始素材

把写这篇稿子需要的东西收拢进来。手头已经够多就跳过这步。

- 被写的东西（产品、服务、优惠、报告、新闻）。
- 它和替代选项的区别。
- 证据——数字、结果、案例、数据。
- 可能的异议和犹豫。

素材太薄时，通过项目调研、向用户追问，或外部调研来补。

### 3. 规划结构编排

用收集到的素材设计稿子的结构。**动笔前把计划给用户看，确认方向。**

结构编排的细节：见 [references/composition.md](references/composition.md)。

### 4. 定调

根据目的、受众和渠道定语气。**动笔前和用户确认。**

- **正式度（Formality）**——随意/口语、专业但亲切、正式/官方。
- **个性（Personality）**——俏皮还是严肃，大胆还是克制，技术腔还是大白话。

### 5. 起草、审阅、打磨

按商定好的计划和语气写。

**流程：**
1. **一气呵成地起草。**写的时候不改。跟着计划走的不完美初稿，胜过打磨好的第一段加之后的卡壳。
2. **自我审阅。**用 [references/anti-patterns.md](references/anti-patterns.md) 对照初稿找问题，再用 [references/clear-writing.md](references/clear-writing.md) 改进。标题、导语、开头还要对照 [references/attention-hooks.md](references/attention-hooks.md) 检查——读者真的被拉进来了吗？
3. **打磨。**通读全文。检查语气一致性、小节之间的衔接，以及所有比需要更臃肿的措辞。

**参考：**
- [references/clear-writing.md](references/clear-writing.md)——清晰、低摩擦行文的技巧。自我审阅和打磨时用。
- [references/anti-patterns.md](references/anti-patterns.md)——常见失败模式。审稿时当检查清单用。
- [references/attention-hooks.md](references/attention-hooks.md)——赢得注意力的标题、导语和开头模式。

## 工作流：改进已有文案

### 1. 先理解现状

通读已有稿子，确认：

- **目的和受众**——写给谁、想达成什么、读者在哪里遇到它。
- **用户的具体诉求**——“写紧凑点”/“提高转化”/“改改语气”是不同的活。如果用户只说了“写好点”，先问清哪个维度最重要，别猜。
- **成功标准**——怎么知道重写成功了？如果现有版本有效果数据（点击率 CTR、转化率 conversion rate、打开率 open rate、回复率 reply rate），要过来。
- **不能动的部分**——必须保留的小节、法律或商标用语、篇幅上限、产品里自带的术语。提前划定禁区，比事后回滚容易。

稿子分量重、又有不清楚的地方，先问再诊断。小幅度的表层调整少问。

### 2. 诊断

读稿子，找出问题。按以下视角依次过：

1. **清晰度（Clarity）**——读者能准确收到意思吗？
2. **结构（Structure）**——逻辑流、过渡、信息出现的顺序。
3. **具体性（Specificity）**——论断有支撑吗？有没有飘在抽象里？
4. **说服力（Persuasion）**——真的推动读者了吗？让人想行动，或想继续读？
5. **语气（Tone）**——对目的和受众而言一致、得体吗？
6. **紧凑度（Tightness）**——有没有冗余、注水、填充物？

**重写前，先把诊断结论给用户看，就修哪些问题、怎么修达成一致。**

### 3. 重写

做商定好的修改。强化核心信息，而不是替换它。
