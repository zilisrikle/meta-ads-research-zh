# 结构编排（Composition）

结构编排是写作中最重要的部分。写第一句话之前先锁定结构——之后的所有决定都立在它上面。

结构编排*不是*文字本身。它是以下内容的安排：

1. **小节设计**——有哪些小节，以及它们出现的顺序。
2. **小节内容**——每个标题、正文和收尾在做什么。

结构编排在记事本上搭，不在成品文字里搭。它是动工前的建筑图纸。真正的写作遵循 SKILL.md 里的原则。

**本文用到的术语：**
- **作品（piece）**——一件完整的成品。一个落地页、一封邮件、一份提案、一篇文章。
- **小节（section）**——作品里的一个区块或划分。
- **结构编排（composition）**——小节如何设计和排序。

写作有两种：

1. **说服型（persuasive）**——为改变读者的行为或信念而写。落地页、广告、邮件、销售演示文稿。
2. **信息型（informational）**——为传递知识或共识而写。报告、内部文档、手册、简报。

这两种模式作用在**小节层面**，不只作用在整篇层面。一个说服型落地页可以含一个信息型的 FAQ 小节；一份信息型报告可以含一个说服型的“为什么是现在”小节。知道每个小节处于哪种模式，是做好结构编排的核心。

---

## 结构编排工作流

### 第 1 步：定义读者的终态

排任何东西之前，先定义**读者读完时应该处于的状态**。之后的所有判断——纳入什么、删掉什么、怎么排序——都以它为参照。终态模糊，结构上的任何决定都定不下来。

### 第 2 步：决定纳入什么、舍掉什么

用终态决定**这篇稿子必须说什么、不能浪费篇幅说什么**。这是结构层面的编辑筛选。

- **说服型**写作，把信息提炼成**一个核心观点**。每个小节都为支撑这一个观点而存在。
- **信息型**写作，纳入读者需要的，不多给。即使有几件事都值得说，凡是不服务于目标的都删。

### 第 3 步：选小节和排序

根据终态，决定**出现哪些小节、按什么顺序**。

**小节阵容的检验标准：**
- 一个小节，一个信息。别压缩。
- 每个小节应该提出一个问题，由下一个小节回答。
- 有没有缺的？有没有多余的？

**连接组织：**小节排成一排还不是结构编排。每个小节应该在读者脑子里种下一个问题，由下一个小节解开。这个连接一断，读者就会觉得“等等，怎么突然到这儿了？”然后跳出。

| 上个小节做了什么 | 它给读者留下的问题 |
|---|---|
| 提出了一个论断 | “我凭什么信？”→ 给证据 |
| 点出了一个问题 | “怎么解决？”→ 给方案 |
| 勾勒了概览 | “给我看细节”→ 给细节 |
| 陈述了一个事实 | “那改变了什么？”→ 讲影响 |
| 介绍了一种方法 | “真有人用它成过吗？”→ 给实证 |
| 把全文总结了 | “那我现在该做什么？”→ 给下一步 |

### 第 4 步：给每个小节定方向

对阵容里的每个小节，沿三个组件定方向。

**标题**——小节许下的“承诺”。读者靠它判断小节其余部分值不值得花时间。
- **说服型小节**——标题本身就是钩子。要拦住读者，把他往下拉。
- **信息型小节**——标题把内容干净、准确地描述出来。理想情况是读者只扫标题就能复原整篇的结构。

**正文**——正文的任务是兑现标题的承诺，兑现到读者被说服需要的程度。选合适的形式：
- **陈述事实**——客观事实就够了时。
- **具体信息——数字、例子、细节**——标题的论断太抽象、读者还想象不出来时。
- **证据——数据、结果、第三方声音**——可信度存疑时。
- **比较/对比**——想让读者在这几个选项里选这个时。
- **分步流程**——想让读者觉得“我真能做到”时。
- **故事**——想要情绪拉力，或一段经历比数字更说明问题时。

**收尾（可选）**——正文把画面填满后，把小节的观点再说一遍，钉牢。正文长时用；小节短时跳过。

## 按文体给的结构编排

这些是参考模板，不是法律。按实际简报调整小节。用四步工作流做判断；模板是起点。

### 落地页

**结构：**

| 小节 | 作用 |
|---|---|
| 首屏（Hero） | 三秒内传达：“这是写给像我这样的人的。”标题 + 支撑句 + 视觉 + CTA + 信任信号。 |
| 问题/共情 | 把读者的痛说出来。让他觉得被理解。 |
| 解决方案 | 把产品/服务包装成解法。先讲收益，不讲功能。 |
| 为什么选我们 | 和替代选项的区别。用数字背书。 |
| 成果/实证 | 具体结果。行业 + 问题 + 结果，一个案例三点。 |
| 客户评价/社会认同 | 真名、真照片、可识别的 logo、媒体报道、奖项。 |
| 产品/服务细节 | 读者实际在为什么付钱：功能、机制、包含什么。读完应该确切知道自己买到什么。 |
| 定价 | 方案对比、价格、包含内容。页面刻意不披露定价时跳过。 |
| 使用流程 | 3–5 步的流程，让上手看起来不难。 |
| FAQ | 五到八个最大的未解疑虑，直接回答。 |
| 保障/风险逆转 | 退款政策、免费试用、安全姿态。 |
| 限时优惠（可选） | “本月免费送 [bonus]”“仅限前 50 名”。紧迫或稀缺放在最终 CTA 附近，只在真实时用。 |
| 最终 CTA + 表单 | 内嵌，字段最少，配化解最后一公里犹豫的微文案（microcopy）。 |

**落地页专用原则：**
- 一页一个目标。别造分叉路。
- 拿掉导航。别给读者出口。
- 首屏必须和把读者带来的东西（广告、邮件、搜索）信息一致。
- 至少三个 CTA：首屏、页中、结尾各一。

### 销售演示文稿/提案

**结构：**

| 小节 | 作用 |
|---|---|
| 执行摘要 | 一页装下整个故事和建议。决策者可能只读这一页。 |
| 问题界定 | 把潜在客户的现状准确地讲回给他听。证明你懂。 |
| 提案 | 你推荐什么，和问题之间有清晰的连线。 |
| 计划 | 谁在什么时候做什么。阶段和里程碑。 |
| 预期成果 | 定量预测，底下附推理过程。 |
| 费用/条款 | 定价用让 ROI 看得懂的形式呈现。 |
| 过往业绩/可信度 | 可比的合作案例、团队介绍。 |
| 下一步 | 读者应该采取的具体行动，推动事情往前走。 |

**提案专用原则：**
- 从潜在客户的问题开场，不从你的公司开场。
- 给他们一个“为什么是现在”。惯性是默认状态；你在和它竞争。
- 用数字。“We will improve performance”太软，落不了地。
- 用*他们*的语言。他们的内部术语、行业黑话，不用你的行话。
- 默认读者扫读。标题和视觉自己要能把论证扛起来。
- 自己先把风险和顾虑摆出来。藏着掖着丢信任。

### 邮件（销售/营销）

**结构：**

| 小节 | 作用 |
|---|---|
| 邮件主题行 | 赚打开。从注意力钩子里取。 |
| 首行 | 在预览窗格里可见。一句话讲清读的理由。 |
| 正文 | 一个信息。短。 |
| CTA | 一封邮件，一个行动。一个按钮或一个链接。 |
| P.S.（附言，可选） | 邮件里被读得最多的部分之一。用来重复关键点或 CTA。 |

**邮件专用原则：**
- 短赢。目标是不滚屏。
- 一封邮件 = 一个信息 = 一个 CTA。
- 主题行承诺了什么，正文必须兑现。标题党式标题烧掉的是以后的打开率。

### 博客文章

**结构：**

| 小节 | 作用 |
|---|---|
| 标题 | 对上读者的搜索意图，赚点击。 |
| 导语 | 这篇写给谁、能得到什么。立住继续读的理由。 |
| 目录（长文） | 展示稿子的形状，让读者跳转。 |
| 正文小节 | 一个标题一个主题。为扫读而建。 |
| 结尾 | 关键点回顾 + 下一步行动（相关阅读、一个 CTA）。 |

**文章专用原则：**
- 读者只扫标题就应该能抓住论证。
- 避免长段落。两到四个句子是最佳区间。
- 用列表、表格和突出引文（pull quote）变换视觉节奏。
- 先解决搜索意图，再往深走。

### 新闻稿

**结构：**

| 小节 | 作用 |
|---|---|
| 大标题 | 一句话讲清核心新闻，陈述事实。不炒作。 |
| 副标题（可选） | 背景细节或支撑大标题的关键数字。 |
| 导语段 | 5W1H——谁、何事、何时、何地、为什么、怎么做——压缩进一段。只看这段就应该清楚整件事。 |
| 正文 | 导语背后的细节：背景、具体信息、相关人的引述。 |
| 固定公司简介（boilerplate） | 标准公司介绍：名称、成立时间、公司做什么、网址。 |
| 联系方式 | 媒体联系人：姓名、邮箱、电话。 |

**新闻稿专用原则：**
- 严格倒金字塔。最重要的信息最先；后面的段落删掉也不影响故事成立。
- 只写事实。不用形容词，不做主观评价。“groundbreaking”“revolutionary”“industry-leading”这类词跳过。
- 观点放进具名人物的引述里。
- 细节写到记者能直接发的程度。

### 案例研究

**结构：**

| 小节 | 作用 |
|---|---|
| 标题 | 先给结果。“How [Company] [achieved result]”。或从结果反推抓注意力：“200% revenue growth——and the problem they had to solve to get there”。 |
| 客户画像 | 行业、规模、背景。让读者认出“这就是我们这样的人”。 |
| 挑战 | 当时卡在哪。具体的痛，具体的数字。 |
| 方法 | 做了什么。为什么选这个方法，落地过程。 |
| 成果 | 定量结果（X% improvement、Y dollars saved）。前后对比。 |
| 客户原声（可选） | 真人具名的引言。兼有事实和感受时最强。 |

**案例研究专用原则：**
- 别断挑战 → 方法 → 成果这条链。
- 结果必须量化。“We're happy with the results”不够。
- 细节要具体到读者能在里面认出自己的处境。

### 手册/帮助文档

**结构：**

| 小节 | 作用 |
|---|---|
| 标题 | 读者读完能做什么。“配置 X。”“怎么做 Y。” |
| 前置条件（可选） | 所需环境、准备工作、目标读者的水平。 |
| 步骤 | 编号动作，一步只做一个动作。用截图和示意图。 |
| 验证 | 步骤做对之后屏幕应该长什么样。 |
| 故障排查（可选） | 常见错误和修法。 |
| 相关文档（可选） | 读者下一步大概率需要的链接。 |

**手册专用原则：**
- 一页一个任务。别把不相关的任务打包。
- 编号步骤里只放读者要做的动作。背景和原理解释放侧栏文字或提示框。
- 别默认已有知识。术语第一次出现就定义。
- 多用截图和示意图。纯文字的操作说明容易跟丢。
