# X Ads Planning（X 广告规划）

从战略到启动交付，规划 X Ads 项目：目标选择、广告系列架构、定向、出价、素材、衡量和运营实践。

## 以实践为先的立场

X Ads 规划应优先关注让广告系列真正跑起来的实践，而不仅仅是让广告系列"合规"的设置。目标、版式、版位和出价设置固然重要，但它们的重要性次于衡量质量、素材质量、落地页质量、受众信号设计、预算充足度和严谨的运营节奏。

在提出广告系列设置之前，先核查以下事项：

| 领域 | 要核实的内容 | 为什么重要 |
|---|---|---|
| 业务结果 | 收入、合格线索、应用事件、品牌认知或对话参与度 | X 的目标菜单不能替代单位经济学 |
| 衡量 | X Pixel、Conversion API / Conversions API、Events Manager、MMP、目录事件、UTM | 弱信号会让优化和报表产生误导 |
| 素材体系 | 差异化概念、移动端适配、首帧冲击力、美学质量、更新计划 | X 的信息流节奏极快；弱素材死得很快 |
| 受众信号 | 关键词、对话、粉丝相似人群（look-alikes）、Custom Audiences、排除项、Optimized Targeting | 定向输入越来越多地充当信号，而非刚性保证 |
| 预算与量级 | 预算与 CPA/CPI 的比例、预期转化量级、测试体量 | 预算太小撑不起碎片化结构 |
| 落地页 | 着陆页、应用商店、结算页、表单、目录、页面速度、信息一致性 | X 能创造注意力；落地页负责转化 |
| 控制项 | 地理、语言、年龄、设备、敏感类别规则、品牌安全、托管产品准入 | 自动化和高级版位需要护栏 |
| 运营节奏 | 每日健康检查、每周优化、素材更新、衡量对账 | 大多数失败源于放任不管或过度干预 |

### 核心运营规则

- 从业务结果和单位经济学出发，而不是从 X Ads Manager 的菜单出发。
- 把优化信号视为战略本身。优先选择量级足够、延迟可接受的最深层可靠事件。
- 区分平台表现与增量价值。再营销、浏览后归因（post-view credit）、品牌自有需求和跨渠道重叠都会夸大 X 的业务贡献。
- 保持结构简单。只有存在真实的控制需求时才拆分广告系列或广告组：目标、预算、经济学、市场、合规、受众、素材测试、购买路径或衡量。
- 有意识地使用 Optimized Targeting。它可以在灵活的定向输入之外扩展，同时遵守地域、语言、年龄、性别、操作系统、设备和排除项的限制。
- 把素材视为首要杠杆。先测试差异化概念和钩子，再测试装饰性变体。
- 除非下游质量、品牌安全和增量价值仍可接受，否则不要追逐便宜的 CPM、CPC、CPE、CPV 或 CPI。
- 对于普通付费广告文案，避免使用话题标签、裸 URL、表情符号堆砌和低质量视觉素材。只有当所选产品明确要求时，才使用托管品牌功能（managed branded features）或 Conversation Buttons。
- 避免持续干预。批量执行有意义的调整，让投放、转化延迟和统计噪声沉淀后再做判断。

### 节奏

默认按以下运营节奏执行，除非账户情况另有指示：

| 节奏 | 重点 | 避免 |
|---|---|---|
| 每日 | 花费异常、投放下滑、审核未通过、追踪/目录/数据流中断 | 每天乱调目标和预算 |
| 每周 | 素材疲劳、受众质量、关键词/搜索意图、KPI 进度、落地页质量 | 凭几天噪声就重构 |
| 双周 | 新素材概念、关键词/受众测试、预算转移、着陆页检查 | 上线大量近乎相同的变体 |
| 每月 | 衡量健康度、Custom Audiences、目录健康度、增量假设、结构复盘 | 任由启动期的假设一直存在 |
| 季度 | 业务模式适配、目标战略、真实来源对账、托管版位角色 | 只汇报 X Ads Manager 的指标 |

### 衡量说明

- X 的指标用于战术优化，而不是最终财务真相。
- 与订单、CRM、应用收入、合格商机、LTV、边际贡献或其他业务真实来源对账。
- 让互动后归因（post-engagement）和浏览后归因（post-view）的假设保持可见。
- 对于应用广告系列，在规划应用安装出价前先配置经认可的 Mobile Measurement Partner（MMP）。
- 对于电商/DPA，核实 X Shopping Manager、产品数据流健康度、目录事件匹配和购买价值。
- X 的衡量基础设施在某些方面不如 Meta 成熟：不要假设 X 上存在 Meta 式的 CAPI Gateway、AEM 或 EMQ。

## 输出灵活性

根据用户的实际需求调整输出。没有硬性要求产出书面规格文档。

| 场景 | 输出 |
|---|---|
| 用户问聚焦的具体问题 | 直接回答并给出推理。不写文档。 |
| 用户想要全貌规划指导 | 行内结构化回复，覆盖相关章节。 |
| 用户明确要求书面计划/规格/简报 | 按要求的格式，行内输出或生成 Markdown 文件。 |
| 用户要从零启动多广告系列账户，且交付物需要交接 | 书面规格通常合适，但除非明确要求，先确认再写。 |

## 工作流程

```text
Step 0: Mode detection             -> New launch or improvement of existing account
    ↓
Step 1: Information gathering      -> Phase A basics -> business-model read -> Phase B details
    ↓
Step 2: Viability + strategy       -> Budget viability -> objective, format, targeting, structure
    ↓
Step 3: Creative + measurement     -> Define creative system, signal design, and operating cadence
    ↓
Step 4: Delivery                   -> Produce the answer, operating plan, spec, or creative brief
```

## Step 0：模式识别

判断适用哪种情形。如不确定，直接问。

| 模式 | 触发条件 | 路径 |
|---|---|---|
| **全新启动** | X Ads 尚未投放，或从零设计新广告系列 | Step 1 -> 2 -> 3 -> 4 |
| **现有账户优化** | 账户已在投放，存在效果问题或改进目标 | Step 1 -> 诊断 -> 改进方案 -> 按需进入 Step 2-4 |

### 改进工作流

对于现有账户，在 Step 1 之后做诊断。用 [references/diagnostic-decision-trees.md](references/diagnostic-decision-trees.md) 对可能根因排序，再提调整方案。

1. **盘点** - 在投广告系列、目标、广告组、预算、出价策略、定向、版位、素材量级和当前 KPI。
2. **问题定位** - 审计衡量、转化质量、受众/定向匹配度、素材疲劳、落地页质量、预算充足度、产品准入。
3. **改进方案** - 按优先级排序的行动项，附证据、预期稳定窗口和应避免的改动。
4. **执行/交接** - 用适合任务的形式记录商定的改动。

## Step 1：信息收集

优先使用已有的项目上下文。只问那些影响推荐、且缺失的信息。

### 阶段 A：基础信息

| 类别 | 要确认的内容 |
|---|---|
| **业务模式** | 电商 / 线索获客 / 应用 / SaaS / 本地 / 媒体 / 品牌认知 |
| **投放产品** | 产品、服务、应用、活动、内容、免费试用、线索磁铁（lead magnet）、新品发售等 |
| **目标** | 核心 KPI：CPA、ROAS、CPL、CPI、CPV、CPE、触达、合格线索率等 |
| **预算** | 月度或日度媒体预算 |
| **落地页** | 网站、着陆页、应用商店、深度链接、产品目录、直播活动或账号主页 |
| **受众** | 地理、语言、年龄/性别（如相关）、客户类型、兴趣、关键词、对话场景 |

完成阶段 A 后，用 [references/business-model-playbooks.md](references/business-model-playbooks.md) 查看对应业务模式的默认策略，再选目标或版式。

### 有用的背景信息

| 类别 | 要确认的内容 |
|---|---|
| 历史 X Ads 表现 | 历史 CTR、CVR、CPA、ROAS、CPI、CPE、CPV、素材经验 |
| 跨渠道结果 | Google、Meta、TikTok、LinkedIn、邮件、自然社媒、SEO、CRM 表现 |
| X 账户状态 | Verified Organizations、Premium、粉丝基数、自然互动、托管服务权限 |
| 衡量 | X Pixel、Conversion API / Conversions API、Events Manager、应用 MMP、产品目录、UTM |
| 素材 | 现有帖子、图片、视频、产品图、达人素材、制作产能 |
| 政策/合规 | 住房/借贷/信用、健康、金融、酒精、就业、政治/社会议题、披露要求 |

掌握细节后，用 [references/budget-planning.md](references/budget-planning.md) 检查预算能否支撑拟定的目标、广告系列组合和学习量级。如果不够，先收窄结构，再进入 Step 2。

## Step 2：可行性 + 战略成型

在确定最终组合之前，综合以下输入：

1. [references/business-model-playbooks.md](references/business-model-playbooks.md) 的业务模式适配。
2. [references/budget-planning.md](references/budget-planning.md) 的预算与信号可行性。
3. [references/measurement-and-signal-quality.md](references/measurement-and-signal-quality.md) 的衡量就绪度。
4. [references/policy-and-account-requirements.md](references/policy-and-account-requirements.md) 的政策/账户准入。
5. 下文各节的目标、版式与购买路径适配。

不要因为某种广告系列类型存在就推荐它。如果预算、事件质量、素材供给、账户准入、目录健康度或衡量能力撑不起，先说明必须解决什么问题。

### 2-1. 广告系列目标选择

X 的目标命名在部分账户流程中处于过渡期。官方公开页面仍列出 **Website conversions**，而其他现行 X 界面使用 **Sales** 和 **Conversions**。规划时用"Website conversions / Sales"，启动前在 X Ads Manager 中核实现行标签。

| 漏斗 | 目标/流程 | 适用场景 | 核心注意点 |
|---|---|---|---|
| 认知 | Reach | 高效获取曝光 | 便宜的触达可能掩盖弱的信息记忆度 |
| 考虑 | Video views | 推动视频观看 | 观看不等于转化意向 |
| 考虑 | Website traffic | 引流到着陆页 | 只在转化追踪未就绪、或流量本身就是目标时用 |
| 考虑 | Pre-roll views | 在优质发布者视频前投放 | 上下文和品牌安全比末次点击 CPA 更重要 |
| 考虑 | Engagement | 推动帖子互动 | 互动质量可能很浅 |
| 考虑 | App installs | 获取应用用户 | 应用安装出价要求配置经认可的 MMP |
| 转化 | App re-engagements | 推动已有应用用户行动 | 需要应用事件衡量 |
| 转化 | Website conversions / Sales | 推动已追踪的网站转化 | Pixel/CAPI 事件质量决定表现 |
| 高级/场景化 | Keywords campaign / Search Ads | 触达搜索意图活跃的用户 | Search Results 版位是必选/默认；可用性可能有差异 |

X **没有**与 Meta Lead Ads 或 LinkedIn Lead Gen Forms 对等的原生线索表单目标。做线索获客时，用 Website traffic 或 Website conversions / Sales 搭配已追踪的表单、CRM 回传和着陆页质量控制。

目标细节、定向、出价和衡量见 [references/campaign-strategy.md](references/campaign-strategy.md)。

### 2-2. 按业务类型的推荐结构

| 业务类型 | 目标/流程 | 结构 | 核心版式 | 衡量优先级 |
|---|---|---|---|---|
| **电商/零售** | Website conversions / Sales；目录就绪时用 DPA | 拓客 + 再营销/目录广告系列 | Dynamic Product Ads、Collection、Image/Video、Carousel | 购买价值、ROAS、利润率、新客 vs 老客 |
| **线索获客** | Website conversions / Sales 或 Website traffic | 拓客 + 再营销 + 信任背书/教育 | Image、Video、Carousel、Keyword Ads | 合格线索、CRM 阶段、线索到商机的 CPL |
| **SaaS / B2B** | Website conversions / Sales；教育内容用 Website traffic | 意图/关键词 + 粉丝相似人群 + 再营销 | Text、Image、Video、Carousel、Keyword Ads | 合格注册、demo、商机 |
| **应用** | App installs 或 App re-engagements | 安装 + 再参与；仅在需要时按操作系统/地域拆分 | Video、Vertical Video、带 App Card 的 Carousel | CPI、应用内事件、留存、LTV |
| **品牌/发布** | Reach、Video views、Engagement | 广覆盖 + 竖视频 + 可选高级版位 | Vertical Video、Video、Image、Takeovers、Amplify | 触达、频次、观看质量、提升度 |
| **直播/活动** | Reach、Video views、Engagement | 活动前 + 直播中 + 活动后再营销 | X Live、Video、Branded Notifications、Takeovers | 注册、观看量、观看时长、切片 |

### 2-3. 广告版式选择矩阵

| 目标 | 首选 | 次选 | 第三选择 |
|---|---|---|---|
| 品牌认知 | Vertical Video Ads | Video Ads | Image Ads / Takeover |
| 网站流量 | 带 Website Card 的 Image 或 Video | Carousel | Keyword Ads |
| 电商销售 | Dynamic Product Ads | Collection Ads | Carousel / Video |
| 线索获客 | 引流到着陆页的 Image/Video | Keyword Ads | Carousel 信任背书序列 |
| 应用安装 | 带 App Card 的 Video / Vertical Video | 带 App Card 的 Carousel | 带 App Card 的 Image |
| 互动 | Text/Image/Video | 有 Polls / Conversation Buttons 时可用 | Branded 功能 |
| 高级场景 | Amplify Pre-roll | Amplify Sponsorship | X Live / Takeover |

### 2-4. 购买路径与准入

| 购买路径 | 适用场景 | 示例 |
|---|---|---|
| 自助 via X Ads Manager | 效果广告系列、测试、标准 Promoted Ads、应用/网站目标 | Image、Video、Carousel、DPA、Collection、Keywords campaign |
| 准入制/账户相关 | 功能权限因账户、市场或工作流而异 | Vertical Video、Amplify Pre-roll、Polls、Conversation Buttons |
| 托管服务/高触点 | 高级预定、赞助、大型活动、品牌功能 | Timeline Takeover、Spotlight Takeover、Amplify Sponsorship、Branded Notifications、Branded Hashtags、X Live |

### 2-5. 选定后的呈现

先呈现方向，再深入细节：

1. 推荐的目标及原因。
2. 广告系列组合概览：广告系列/广告组数量及各自角色。
3. 推荐的版式和购买路径。
4. 定向姿态，包括是否使用 Optimized Targeting。
5. 出价策略、预算分配和衡量前置条件。

## Step 3：素材 + 衡量设计

这一步把素材、定向和衡量串起来。在 X 上，快节奏信息流的素材、关键词/对话场景和优化信号必须互相强化。

### 素材设计原则

- 一次只讲一个核心信息、解决一个受众问题。
- 尽早露出产品、证明、结果或对话钩子。
- 按移动端信息流和竖屏环境优先设计。
- 复用 Meta/TikTok/Instagram 素材时用 4:5 和 2:3；X 在 2026 年扩展了这些比例以提升素材可移植性。
- 视频配字幕或文字叠加，但保持清晰不杂乱。
- 普通付费广告文案不要带话题标签，除非使用托管品牌功能或 Conversation Button。
- 有 Website Cards 或 App Cards 时，文案中不要放裸 URL。
- 把 Aesthetic Score 指引视为运营上的重要参考，但除非当前账户可见该指标，否则不要声称它是保证可见的指标。

素材原则、Aesthetic Score 指引、钩子设计、CTA 选择和测试节奏见 [references/creative-fundamentals.md](references/creative-fundamentals.md)。

### 衡量设计

在敲定启动建议前，先用 [references/measurement-and-signal-quality.md](references/measurement-and-signal-quality.md)。

| 业务类型 | 优先信号 | 注意点 |
|---|---|---|
| 电商/零售 | 带价值的 Purchase；产品级事件 | 收入 ROAS 可能掩盖利润率、退货、折扣和老客偏向 |
| 线索获客 | 量级允许时用合格线索 / CRM 阶段 | 原始线索可能训练出便宜但低质的量 |
| SaaS/订阅 | 合格注册、demo、激活、留存价值 | 试用/注册量可能在激活很弱时产生误导 |
| 应用 | 安装 -> 应用内事件 -> 留存价值/LTV | 不要永远优化安装 |
| 品牌/认知 | 触达、频次、观看质量、提升度/需求代理指标 | 末次点击 CPA 会低估上层漏斗价值 |
| 直播/活动 | 注册、提醒订阅、观看量、观看时长、活动后行动 | 活动价值取决于时机和跟进 |

### 平台说明

- X Ads 的产品名称、准入、规格和托管服务可用性变化很快。最终启动前务必在 X Ads Manager 或与 X 代表处核实当前可用性。
- 官方 X 公开页面目前仍沿用 Website conversions、Conversion API 等旧标签，而其他界面使用 Sales、Conversions 或 Conversions API。需要时保留两种说法并核实账户界面。
- Timeline Takeover、Spotlight Takeover、Amplify Sponsorship、Branded Hashtags、Branded Notifications、X Live 等高级产品可能需要托管服务权限或 X Next/客户团队支持。
- 基准值随市场、品类、素材、目标、出价和衡量质量差异极大。把 CPM、CPC、CPV、CPE、CPI、CPA 和 ROAS 基准视为规划输入，而不是承诺。

## 相关工作流

- 做跨平台媒体组合设计时，使用 Google Ads、Meta Ads、TikTok Ads、LinkedIn Ads 或其他平台的规划 skill。
- 用户需要成品广告文案或可投产的素材时，使用素材或文案工作流。
- 用户需要 X Pixel、Conversion API / Conversions API、应用 MMP、目录数据流或 CRM 归因的实施时，使用分析/追踪工作流。
