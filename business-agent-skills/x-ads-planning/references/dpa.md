# 动态产品广告（Dynamic Product Ads）

动态产品广告（Dynamic Product Ads）帮助广告主根据用户行为和预测兴趣，从产品目录中向用户投放相关产品。

规范来源：X 动态产品广告设置文档（https://business.x.com/en/help/campaign-setup/create-a-dynamic-product-ads-campaign）与创意广告规范（https://business.x.com/en/help/campaign-setup/creative-ad-specifications）。最后核验：2026-04。

## 类型

| 类型 | 用途 |
|---|---|
| DPA 再营销（Retargeting） | 向看过、加购或以其他方式互动但未购买的用户展示产品 |
| DPA 拓新（Prospecting） | 向预测感兴趣的新用户展示目录产品 |

## 前置要求

- 在 **X Shopping Manager** 中上传并管理产品目录。
- 配置 X Pixel 和/或 Conversion API / Conversions API 事件。若没有 Pixel/CAPI，DPA 可能只能使用链接点击优化。
- 配置相关关键事件，如页面浏览（Page View）、内容浏览（Content View）、加购（Add to Cart）和购买（Purchase）。
- 与目录产品匹配的 `contents` 参数或产品标识符。
- 包含准确 ID、标题、价格、库存、图片、URL 和分类的产品 Feed。
- 可保持产品数据持续更新的 Feed 文件与同步流程。X Shopping Manager 支持大型目录；当前文档引用上限为 100 万产品或 8GB 的 Feed 文件。
- 按筛选条件创建的产品集（Product Sets），用于系列特定的选品。
- 尽可能使用 UTM 和产品级报告。

## 系列设计

| 系列 | 受众 | 作用 |
|---|---|---|
| 再营销 | 近期浏览者、加购放弃者、产品互动者 | 挽回高意向用户 |
| 拓新 | 宽泛或模型化受众 | 利用目录相关性寻找新客户 |
| 交叉销售 / 追加销售 | 现有客户 | 推广互补产品 |

当预算、报告或受众意图存在差异时，保持再营销和拓新系列相互独立。

对于再营销系列，在 DPA 设置过程中创建目录行为受众（Catalog Activity Audiences）。在能改善受众规模或质量的地方使用相关的名单自定义受众（List Custom Audiences）。

只有当 Feed 和事件质量足以支撑个性化时才使用 DPA。对于薄弱的目录或非常小的再营销池，产品导向的图片、轮播或精选广告测试可能比强行使用 DPA 更有用。

## 创意与文案

目录信息承担了大部分工作。用文案补充上下文：

- 利益点或产品品类框架。
- 加购/浏览放弃提醒。
- 新品或热销框架。
- 相关时使用促销或季节性话术。

如果折扣话术会削弱品牌定位或培养低毛利需求，避免过度使用。

## 度量

| KPI | 用途 |
|---|---|
| CPA / 购买成本 | 获客效率 |
| ROAS | 收入效率 |
| 边际贡献 | 产品毛利差异较大时更有用 |
| 新客 vs 老客 | 增量与获客质量 |
| 产品级表现 | Feed 与选品决策 |

## 常见错误

- 错误的产品 ID 导致事件与目录匹配失败。
- 缺少有效事件匹配和报告所需的价值（value）、货币（currency）、`contents` 或购买/内容参数。
- Feed 中包含缺货产品。
- 产品图片质量差。
- 再营销窗口超出购买周期过宽。
- 只报告收入 ROAS，缺少毛利或增量视角。

## 诊断

| 症状 | 可能原因 | 应对 |
|---|---|---|
| 展示的产品很少 | 产品集过窄或 Feed 错误 | 检查 X Shopping Manager 审批状态、筛选条件、库存和图片 URL |
| 再营销投放不足 | 目录行为受众过小 | 在适当处补充相关的名单自定义受众 |
| ROAS 看起来不错但利润薄 | 低毛利产品占主导 | 按毛利、库存或品类拆分产品集 |
| 产品不匹配 | 事件 `contents` 值与目录 ID 不一致 | 对照目录 ID 审计 Pixel/CAPI 参数 |

## 运营节奏

- 每日：检查 Feed 同步、被拒产品和事件健康度。
- 每周：审视产品级花费、收入、毛利和库存状态。
- 每月：围绕毛利、季节性、新品和库存刷新产品集。
