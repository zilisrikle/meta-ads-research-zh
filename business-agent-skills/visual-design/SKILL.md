优秀的设计不是最后一层收尾——它是一连串关于目的、语境和视觉系统的决策，层层叠加，凝结成最终的成品。本技能是做好这些决策的手册，无论载体是一个一次性的海报，还是完整的产品 UI。

## 工作流

### 1. 澄清目标

先搞清楚你到底在做什么。

从最上层开始——交付物是网站、网页应用、移动应用、桌面应用、演示文稿，还是创意？先把这个钉死。

然后往下钻：
- 这是哪种界面？
- 涉及哪些组件？
- 有哪些页面？

有任何不清楚的地方，去问用户。把需求和意图挖到不留模糊为止。

当简报含糊，或开始新项目之前，至少确认以下几点：

- **可参考的现有资产**：有没有设计系统、UI 套件、代码库、截图或竞品示例可看？没有的话，去要一些。
- **想要几个版本**：整体流程或具体页面，想并排比较几个方案？
- **探索方向**：稳妥的、符合规范的执行？更新颖的视觉或交互？还是两者混合？
- **重心放在哪里**：流程/UX、文案、视觉还是动效——精力应该花在哪？
- **调性（Tone）**：这是给谁的，应该是什么感觉？

不要把问题一抛出去就自己动手干。等答案回来再往下走。

何时提问的经验法则：

- "这是 PRD，给我做个 deck" → 问受众、调性、篇幅。
- "根据这份 PRD 做一个 10 分钟的 Eng All Hands deck" → 信息够了，不需要提问。
- "把这张截图做成可交互的原型" → 只有从图片看不清行为时才问。
- "做 6 页讲黄油历史的幻灯片" → 很含糊，多问。
- "把这个引导流程做成原型" → 多问。
- "照着这个代码库复刻作曲器 UI" → 不需要提问。

任务越新、越大、越模糊，就问得越多。小改或跟进，就少问。

### 2. 引入已有语境

好的设计建立在已有语境之上，而不是凭空发明。从零开始是最后手段——那是最容易得到平庸模板结果的路。动手之前，先过一遍这个清单：

1. **`DESIGN.md`**（项目的设计系统）——如果存在，就遵循它对颜色、排印、组件样式等的规定。
2. **现有代码库 / UI 套件**——仓库里已有的组件和设计 token，是判断调性最可靠的参照。找已有实现、设计系统、UI 库。匹配现有 UI 时，动手前先观察**视觉词汇**：
   - 文案语气（祈使 / 描述 / 口语等）
   - 配色和色温
   - hover / focus / active / disabled 状态的表达方式
   - 动画风格和时长
   - 阴影、卡片、版式模式
   - 信息密度（紧凑 vs. 疏朗）
   动笔前先写 2–3 行观察记录。
3. **品牌资产**——logo、图像、字体。去仓库里找资源文件夹。
4. **参照（References）**（竞品、灵感截图、URL）——有助于对齐调性和方向。

如果没有任何这些语境就开始设计，几乎一定会走向平庸。如果需要的语境拿不到，开始之前先去要。

如果没有 `DESIGN.md`，按规模决定：
- 长期项目、页面多 → 写一个。
- 一次性小体量设计 → 不写。
- 不确定 → 问用户。

真的要写 `DESIGN.md` 时，也不需要每个章节都写。只写成品实际需要的部分。怎么写、怎么维护见 [references/design-md-guide.md](references/design-md-guide.md)。[examples/](examples/) 目录里有以真实品牌为原型的设计系统——先看 [examples/README.md](examples/README.md)，它按调性分组（极简/高级、温暖/编辑、开发者/技术、张扬/表现、AI 原生），开文件前先选 1–2 个锚点。用它们来：
- 参考 `DESIGN.md` 的格式和详细程度。
- 参考色彩策略、排印层级、阴影系统等。
- 作为起点——如果某个示例品牌接近你的目标，就在它的基础上改。

### 3. 把视觉系统写成文字

动手做之前，先简要写下你要用的**视觉系统**。如果都放在脑子里就动手，判断力会做到一半漂移，最终失去整体感。

至少 5–10 行笔记，覆盖：

- **版式（Layout）**：分节标题、标题、图片、正文的基础版式模式。
- **色彩（Color）**：背景色怎么用（用哪几种、怎么切换）。一页或一个 deck 里背景色最多一到两种。
- **排印（Typography）**：标题 vs. 正文的层级、字重和字距策略。
- **装饰（Decoration）**：边框 / 阴影 / 背景色对比，三选一来承载层级。
- **你要做出差异化的地方**：排印、色彩、构图、装饰、动效里选一到两个轴来表达身份。只选一到两个。

如果 `DESIGN.md` 已经存在，这份笔记基本就是照着它填。跳过这一步，你会在一页一页、一节一节地积累即兴决策，整份作品会读起来很散。

**尽早拿出来对齐**：像个初级设计师拿着方案去找经理过一遍一样，早点分享这份笔记（假设、语境、你选的视觉系统）。在深入之前先达成一致。一个确认过的骨架，好过一版要推翻重做的成品稿。第一版全是占位符也没关系——快出、快反馈。

### 4. 开始构建

目的、语境、视觉系统都钉死后，开始构建。选对载体的工具，沿着本技能里的原则和质量线工作。整个过程中时刻想着四个设计原则：统一、成组、强调和可视化。

构建的同时，也对照 [references/anti-ai-aesthetic.md](references/anti-ai-aesthetic.md) 检查，确保你没有无意识地滑向平庸的模板中间值。这不是用户明确说「别做得像 AI 生成的」才看的参考；把它当作**对抗滑向 bland median 的标准检查**。

但话说回来，「避开常见选择」本身不是目的。现有品牌、`DESIGN.md` 和产品语境优先；在这些约束里刻画差异化。而且也不需要在每个维度都做出差异——排印、色彩、构图、装饰、动效里有一两个做出差异就够了。在工作中和打磨阶段都用 anti-ai-aesthetic 检查问自己：「这个选择有理由吗？」「这个感觉属于*这个*项目吗？」

## 优秀设计的标志

无论什么成品，都以这些为目标：

- **即时可读性（Immediate legibility）**：看一眼就知道这是什么。不用阅读——结构、含义、操作方式要瞬间落位。需要思考得越少越好。
- **品牌召回（Brand recall）**：看到设计就想起品牌。当色彩、logo、语气、版式模式一致时，哪怕一块色卡或一个轮廓都能唤起品牌。
- **无意外**：观众的预测——「这个大概会做 X」「那个东西大概是干这个的」——都应成立。可预测性不是无聊，它建立信任和舒适。
- **注意力引导**：视线和操作自然流动；用户永远不用问「接下来看哪」。版式、视觉重量和编排把信息按正确顺序递出去，用户感觉不到背后的工作。
- **减法（Subtraction）**：设计的好坏，同样取决于你删掉了什么。克制填充空间的冲动——删掉多余的，剩下的才有分量。不要为了填空塞填充文案、空架子章节或无来源的数字/图标/数据（data slop）。如果某节显得单薄，那是版式和构图的问题，不是内容不够。
- **细节的工艺感**：像素级的对齐、一致的间距、流畅的过渡——单独看都不起眼，合在一起决定整体是粗糙还是讲究。
- **调性契合**：设计的情感调性必须和语境、受众匹配。功能正确但调性跑偏，会让人觉得「哪里不对」，拖累整体。
- **加东西先问**：当加一个章节、一页、一行文案、一点装饰*似乎*会有帮助时，先提议，不要直接做。用户更了解受众和目标。特别不要为了填空而加内容。
- **占位符好过粗糙的自制资产**：如果没有图标、插画、照片、logo，不要硬造。用明显是占位符的东西——一块色块、一个带标签的框（`[Product photo]`、`[Hero image]`），任何明显在说「真东西会放这里」的东西——然后去找用户要真实资产。一处粗糙的自制资产会拖累整件作品的品质。**在高保真作品里，占位符永远比糟糕的自制资产质量更高。**

## 设计的两个维度

设计建立在两条轴上：**功能**和**艺术**。它们是地基，你要时刻平衡两者。

### 功能（Function）

设计满足需求的程度、提供的能力。用户达成目标、信息准确落地、没人卡住——这都是功能。

### 艺术（Art）

视觉之美、情感拉力、独特的观点。打动人、留在记忆里的能力。

### 如何平衡

功能和艺术不是严格的零和——两者都可以做得很好。但一方推过头，另一方会受损：

- **艺术太多**：功能崩掉。美但不好用，或者信息没传达到。
- **只有功能**：艺术蒸发。好用但没味道、记不住。

### 真实工作中的优先级

商业设计里不会为了艺术牺牲功能。**功能是下限**，而且大多数时候它占主导。

但「功能够了就行」是错的态度。以功能为地基，不断寻找艺术能提升作品的地方。构建时两个问题都问：「这个好用吗？」「这个有表达力吗？」——检查自己没有滑向某一边。

如果你想付出真实的功能代价去推艺术，见 [references/artistry.md](references/artistry.md)。

## 设计的两大类型

载体从根本上改变设计的组装方式。动手前先确定你在做哪一类。

### 静态设计

演示文稿、幻灯片、PDF、图像创意、海报、印刷。**没有动效的载体。**

你只有一帧（或几帧）来承载一切：靠视线流动、信息优先级和留白。一帧静帧要扛起全部，没有时间轴可依靠。

### 动态设计

网站、应用、仪表盘。**动效和交互可用的载体。**

实际用多少动效是另一回事——关键是*选项*存在。这是和静态设计最深层的区别。过渡、hover、滚动联动、状态变化——任何用到时间的、逐步揭示的东西。

动态设计里，**用户如何体验**和构图同样重要。渐进披露、认知负荷、状态设计、反馈、流程、降低交互成本 → [references/ux-ui.md](references/ux-ui.md)。

## 四个设计原则

这四个原则无论设计偏功能还是偏艺术都同样适用。

### 1. 统一（Unity）

角色相同的东西，给相同的处理。同样的字体、同样的字号、同样的颜色、同样的版式、同样的组件形状——角色相同，表达就相同。

统一破裂时，观众会想「等等，这俩是不同的东西吗？」统一成立时，同类事物被瞬间识别。统一是整个设计秩序和信任感的来源。

### 2. 成组（Grouping）

一整个信息单元应该有清晰的边界。观众要能看出「这一组东西是一个整体，到这里结束」。

方法很多——卡片、节标题、留白、分割线、背景色切换。方法次要，边界落位重要。没有边界，观众分不清谁和谁是一伙，理解就断了。

### 3. 强调（Accent）

用重量变化控制阅读顺序。字号、字重、颜色、留白——用它们说「这是重要的部分」「从这里开始看」。

没有对比，观众找不到入口，信息浮不上来。一份优秀设计能一眼读懂，正是因为强调放对了位置。

### 4. 可视化（Visualization）

用视觉元素强化那些纯文本或数字讲不清楚的想法。图片、图标、图表、图解——任何「看一眼就懂」的东西。

目标是「不读也懂」。数据用图表、功能用图标、概念用图解。选对视觉，理解的速度和准确度都大幅提升。

## 设计的构件

构成设计的主要组件。不是每次都要读完所有参考——按成品需要取用。

- **色彩（Color）**——品牌色、背景、文字、强调色、状态（成功 / 错误 / 警告），以及边框和阴影的色调。每种颜色都要有角色；调色板要感觉成一体 → [references/color.md](references/color.md)
- **排印（Typography）**——字体家族、字号层级（display → heading → body → caption）、字重、行高、字距。有文字的设计，排印质量决定设计质量 → [references/typography.md](references/typography.md)
- **版式与间距（Layout & spacing）**——网格、容器宽度、元素间距系统。定一个基础单位（比如 8px），用一致的间隔制造节奏和秩序 → [references/layout.md](references/layout.md)
- **组件（Components）**——按钮、卡片、输入框、导航、徽章等。定形状、颜色、内边距、圆角、阴影和交互状态（hover / focus / active / disabled）→ [references/components.md](references/components.md)
- **深度与层级（Depth & elevation）**——用阴影、边框或背景亮度变化表达层级。设计分明的层级：平面 → 微抬升 → 卡片 → 弹窗 → … → [references/depth.md](references/depth.md)
- **响应式（Responsive）**（只有需要跨多设备多尺寸交付时）——适配屏幕尺寸的策略。断点、列折叠、字号缩放、触控目标 → [references/responsive.md](references/responsive.md)
- **动效与交互（Motion & interaction）**（仅动态）——动画、过渡、hover 效果、滚动联动。动效必须服务于目的；不要为了装饰而动 → [references/motion.md](references/motion.md)
- **图像与图标（Imagery & iconography）**——摄影、插画、图标、logo。风格一致和颜色、排印同样重要：一个粗糙的图标或跑调的库存图会拉低整件作品的观感。定一个图标家族（线性 vs. 填充、线宽、圆角）和一个图像方向（摄影 vs. 插画、暖 vs. 冷、写实 vs. 抽象），然后坚持。拿不到真实资产时，遵循「优秀设计标志」里的占位符规则——带标签的框永远好过糟糕的自制资产。
