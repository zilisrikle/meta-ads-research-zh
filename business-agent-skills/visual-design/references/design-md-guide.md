# DESIGN.md 写作指南

`DESIGN.md` 每个章节怎么写的参考：遵循的规则、工作的顺序、要避的坑。

---

## 选章节

`DESIGN.md` **不需要每个章节都写**。只写成品的目标、规模、载体实际要求的部分。

**必写章节（几乎任何项目都成立）：**
- **视觉主题与氛围（Visual Theme & Atmosphere）**——整体方向。没有它，单个 token 会散。
- **调色板与角色（Color Palette & Roles）**——色彩是任何设计的地基。
- **排印规则（Typography Rules）**——几乎没有设计离得开文字。

**按成品加的章节：**
- **组件样式（Component Stylings）**——成品含 UI 组件时（网站、应用、邮件模板）。
- **版式原则（Layout Principles）**——网格或间距不简单时（多节落地页、仪表盘）。
- **深度与层级（Depth & Elevation）**——阴影或层级在场时（卡片、弹窗）。
- **响应式行为（Responsive Behavior）**——跨多设备交付时。
- **Do's and Don'ts**——长期项目或多人协作的东西，规则容易漂移。

**不需要的情况：**
- 幻灯片或 PDF → 排印 + 色彩 + 视觉主题常常就够。
- 单张图片横幅 → 完全不需要 `DESIGN.md`（`SKILL.md` 里的原则够用）。
- 小的一次性作品 → 从最小版本开始，按需加。

拿不准时，从最小版本开始，意识到「这里没规则会漂移」的那一刻就加一节。

## 逐节指南

### 1. 视觉主题与氛围

用有感染力的语言捕捉情绪、密度、美学哲学。读懂项目的意图，沿这几个轴定方向：

- **密度（Density）：**「画廊式疏朗」→「日常应用的平衡」→「驾驶舱级高密度」
- **变化度（Variance）：**「可预测的对称」→「偏移的非对称」→「艺术的混沌」
- **动效（Motion）：**「静态克制」→「流畅 CSS」→「电影感编排」

组合成一段描述整体氛围的文字。示例："An interface of restrained, gallery-like openness, with confidently asymmetric layouts and fluid spring-physics motion. The mood is clinical yet warm — like a well-lit architecture studio where every element earns its place through function."

### 2. 调色板与角色

每个颜色定义为**描述性名称 + 十六进制 + 功能角色**。分组：

- **主色（Primary）：** 背景表面、文字色、品牌色。
- **强调色（Accent）：** CTA、活跃状态、focus 环（一个项目最多一个；饱和度 80% 以下）。
- **中性色阶（Neutral scale）：** 标题、正文、次要文字、元数据、禁用态。
- **状态色（Status）：** 成功（绿）、错误（红）、警告（琥珀）。
- **边框与阴影（Borders & shadows）：** 边框色；阴影色相（中性，或往品牌色染）。

示例条目：
```
- **Canvas White** (#F9FAFB) — primary background surface. Warm-leaning neutral.
- **Charcoal Ink** (#18181B) — primary text. Zinc-950 depth for warmth.
- **Steel Secondary** (#71717A) — body text, descriptions, metadata.
```

**约束：**
- 一个项目里不要混暖灰和冷灰。

### 3. 排印规则

定义字体家族、字号 / 字重 / 行高 / 字距层级。

**要写明的：**
- **展示 / 标题：** 字体名、字重、字距、行高、scale。
- **正文：** 字体名、字重、行高（往宽松靠）、最大行长（建议 ~65 字符）。
- **等宽：** 代码块、元数据、时间戳用。
- **Scale：** 每个字号的具体值（流体缩放优先用 `clamp()`）。

层级表达成表格：

| 角色 | 字体 | 字号 | 字重 | 行高 | 字距 | 备注 |
|------|------|------|--------|-------------|----------|-------|

**设计原则也要写下来：**
- 层级靠字重和颜色建立，不只靠字号。
- 标题字号越大字距越紧（渐进字距）。
- 正文用常规字重、标题用标题字重的规则。

### 4. 组件样式

每个主要组件，定死形状、颜色、阴影、交互状态的具体值：

**按钮：**
- 背景、文字色、内边距、圆角、字号 / 字重。
- hover 态（背景偏移；不要发光）。
- active 态（按压触感：`-1px translateY` 或 `scale(0.98)`）。
- focus 态（强调色 ring）。
- 变体：主要、次要（幽灵 / 描边）、第三级。

**卡片 / 容器：**
- 背景、边框（颜色、宽度、不透明度）、圆角、阴影（多层阴影的具体值）。
- 内部 padding、hover 行为。
- 层级只在传达层级时用。高密度版式里，用 `border-top` 分割线或负空间代替。

**输入框 / 表单：**
- 边框、背景、文字色、占位符颜色。
- 标签在输入框上方，辅助文字可选，错误文字在下方。
- focus ring（强调色、偏移值）。
- 用不用浮动标签（偏好：标签永远可见，包括聚焦时）。如果用浮动标签，明确写出来并给理由。

**导航：**
- 吸不吸顶；背景怎么处理（模糊、不透明度）。
- 链接字体 / 字重 / 颜色、hover 态。
- CTA 按钮位置。
- 移动端怎么收。

**加载态：**
- 优先骨架屏（shimmer）。尺寸和圆角和真实内容对齐，加载时版式不跳。
- 如果用 spinner，选贴合品牌语气的。骨架屏通常在版式稳定和感知速度上赢。

**空态：**
- 一组插画或图标构图加引导文案。
- 只写 "No data" 是 forbidden。

**错误态：**
- 行内、带语境。强调色下划线或边框。清晰的恢复操作。

### 几何和形状的翻译

把技术性的 `border-radius` 值和版式数字翻译成物理描述。`DESIGN.md` 是设计语言文档，不是 CSS 参考——把原始值翻译成它*看起来、摸起来*什么样：

- `rounded-full` / `9999px` → "pill-shaped"
- `rounded-lg` / `12px` → "generously rounded corners"
- `rounded-md` / `8px` → "subtly rounded corners"
- `rounded-sm` / `4px` → "lightly rounded"
- `rounded-none` / `0px` → "sharp, hard-edged corners"

阴影强度、间距感、版式密度同理——用文字描述观感，不只给数字。

### 5. 版式原则

**网格和结构：**
- 基于 CSS Grid。不用 flexbox 百分比算术（`calc(33% - 1rem)` 之流）。
- 最大内容宽度（比如 `max-width: 1400px`，居中）。
- 横向 padding（移动端 `1rem`，平板 `2rem`，桌面 `4rem`）。

**间距系统：**
- 基础单位（比如 8px）和 scale。
- 章节之间的纵向节奏。

**圆角 scale：**
- 按用途分档（比如 micro 2px → standard 4px → cards 8px → panels 12px → pill 9999px）。

**元素不重叠：**
- 每个元素占据自己清晰的空间区。
- 不用绝对定位堆内容。

**整视口章节：**
- 用 `min-height: 100dvh`。永远不用 `height: 100vh`（iOS Safari 地址栏）。

### 6. 深度与层级

阴影级别定义成表格：

| 级别 | 处理 | 用途 |
|-------|-----------|-----|
| 平面（0 级） | 无阴影 | 页面背景、行内文字 |
| 环境（1 级） | 细腻阴影 | 微抬升的卡片、hover 提示 |
| 标准（2 级） | 标准阴影 | 卡片、内容面板 |
| 抬升（3 级） | 更强的阴影 | 功能卡片、下拉菜单 |
| 纵深（4 级） | 多层阴影 | 弹窗、浮动面板 |

**阴影哲学也要写：**
- 阴影色相（中性灰，或往品牌色染）。
- 多层做法（近层和远层什么时候组合）。
- 负 spread 的用法。

### 7. Do's and Don'ts

为了守住设计意图，两边都明确列出。

**Do 示例：**
- 所有文字应用所选字体的 OpenType 特性。
- 标题用指定的字重。
- 阴影染品牌色。
- 标题文字用深海军蓝，不用纯黑。

**Don't 示例：**
- 标题不要用 bold (700+)。
- 卡片或按钮不要用大圆角（12px+、pill 形）。
- 阴影不要用中性灰——永远染品牌色。
- 不要用纯黑（`#000000`）。
- 交互元素不要用暖强调色。

### 8. 响应式行为

**断点：**

| 名称 | 宽度 | 关键变化 |
|------|-------|-------------|
| 移动端 | <640px | 单列、更小的标题、卡片堆叠 |
| 平板 | 640–1024px | 2 列网格、中等 padding |
| 桌面 | 1024–1280px | 完整版式、3 列功能网格 |
| 大桌面 | >1280px | 内容居中、边距慷慨 |

**移动端优先折叠（< 768px）：**
- 所有多列版式严格折成单列。没有例外。
- 不许横向滚动。横向溢出是严重事故。

**字号缩放：**
- 标题用 `clamp()` 缩放。
- 正文字号下限 `1rem`。永远不低于 `14px`。

**触控目标：**
- 每个可交互元素至少 `44px`。
- 可点击项之间间距慷慨。

**折叠策略：**
- 导航：横向链接 → 汉堡菜单。
- 功能卡片：3 列 → 2 列 → 单列堆叠。
- 章节间距：从桌面到移动端按比例缩小。

**测试视口：**
- 在 `375px`（iPhone SE）、`390px`（iPhone 14）、`768px`（iPad）、`1024px`（小笔记本）、`1440px`（桌面）验证。

## 写作规则

- **描述性。** 跳过 "blue"、"rounded" 这种通用词。用 "deep-sea cerulean (#0077B6)" 或 "generously rounded corners"——说它实际长什么样。
- **功能性。** 每个元素给角色。除了颜色名和尺寸，写它是干什么的（"primary CTA"、"metadata display"）。
- **一致性。** 全篇用同一套词汇。同一个颜色不在两个地方叫两个名。
- **精确。** 描述性名称后面括号跟十六进制、rem 或像素值。自然语言描述和精确技术值都要。
- **可视化。** 写到读者能在脑子里重建设计。这是「设计的描述」，不是「CSS 清单」。
- **讲清为什么。** 除了*是什么*决策，说*为什么*。为什么这个颜色，为什么这个字重，为什么这个间距。
- **表态。** 写一份执行这个项目特定美学的文档，不是中性模板。

## 工作顺序

1. **先定氛围**——钻进 token 之前，先拿到项目的情绪。
2. **找模式**——浮现一致的间距、尺寸、样式模式。
3. **语义命名**——颜色按用途命名（"Electric Blue — for productivity tools"），不按长相（"blue"）。
4. **尊重层级**——记录视觉重量如何传达重要性。
5. **编码禁区**——反模式和规则同样重要。列出不做的事。

---

## 要避的坑

- 技术黑话不翻译（写 "generously rounded corners"，不写 `rounded-xl`）。
- 漏十六进制，或只靠描述性名称——两者都要。
- 忘了写元素的功能角色。
- 氛围描述太虚。
- 跳过小细节——阴影、间距模式。
- 忽视反模式清单——那是把输出抬到 premium 的东西。
- 默认「安全」的通用设计，不逼出一套 curated 的美学。
