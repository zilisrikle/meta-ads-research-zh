# UX 与 UI 原则

动态设计——网站、应用、仪表盘——重要的不只是长什么样，更是**用户体验到什么**。下面的原则是为设计"用户不迷路、不别扭、直达目标"的界面。

---

## 信息优先级与渐进披露

别一次全摊出来。只给用户此刻需要的；细节等人要了再给。

- **先给**：用户最常用的信息和操作。这是屏幕的主角。
- **按需展开**：详细设置、更多选项、补充信息。用手风琴、抽屉、"查看更多"渐进披露。
- **藏起来**：高级设置、极少用的功能。收进设置页或子菜单。

克制住塞满的冲动。屏幕上信息越多，单个信息的认知分量越轻。

---

## 降认知负荷

别让用户的大脑加班。越要动脑，流失越多、出错越多。

- **减选项**：三个按钮胜过十个。选项太多瘫痪（选择悖论）。
- **别考记忆**：别设计"第 3 步要记得第 1 步输了什么"。需要的信息就地给。
- **守惯例**：logo 左上、菜单在上、CTA 用醒目的颜色——别打破用户在别处学到的模式。自创控件是学习税。
- **给默认值**：有合理默认值的表单比空表单好做得多。

---

## 状态设计

界面不只有"正常"一种状态。状态没设计，用户撞见意外画面就懵。

- **空态**：还没数据时给什么看。只有"No data"没用。告诉用户下一步做什么。
- **加载**：等待时出现什么。骨架屏、进度条、spinner。什么都不给，App 像卡死了。
- **报错**：说清哪儿错了、怎么修。不是"出错了"，是"邮箱格式不对"。恢复路径明确。
- **成功 / 完成**：操作成了的反馈。保存、提交、删除——不确认，用户悬着。
- **局部状态**：搜出零结果、列表到底、断网。每个"万一"都设计了吗？

组件状态（悬停、聚焦、禁用、加载等）的视觉处理见 [components.md](components.md)。

---

## 反馈与响应

用户每个动作都要有回应。动作没反应，用户想"坏了？"还是"没点上？"

- **即时反馈**：悬停和点击 100ms 内有反应。这是"动作收到了"的最低速度。
- **给进度**：长操作暴露进度。黑着等的每一秒都显得更长。
- **确认结果**：完成后展示变了什么。保存弹 toast、删除做移除动画。

反馈不只靠视觉。**触感**和**声音**也是反馈通道。确认（发送、删除）时 轻微的触感振动，不用看就知道"收到了"。支付完成或告警的声音比视觉更抓注意力。滥用招人烦——留给真重要的时刻。

反馈的视觉实现见 [motion.md](motion.md)（时长、缓动）和 [components.md](components.md)（交互状态）。

---

## 可供性——让可交互看得见

按钮就得像按钮，链接就得像链接，输入框就得像能往里输。交互的东西不像可交互，用户找不到。

- **可点的像可点的**：按钮给填充或边框；链接给下划线或变色。太平的设计分不清哪儿能点。
- **光标变化**：交互元素用 `cursor: pointer`。光标不变读作"点不了"。
- **状态视觉区分**：选中/未选中、开/关、展开/收起——当前状态一眼读出。

支持可供性的组件模式见 [components.md](components.md)。

## 流程与导航

到目标的步数短而清。永远别让用户出现"我接下来该干嘛？"

### 任务完成流

- **砍步数**：注册、结账、设置——每一步都审。能砍就砍。
- **展示位置**：多步流程里展示当前在哪、还剩几步（步骤条、进度条）。
- **允许撤销**：犯错好恢复。"返回"按钮、撤销、确认框。删除这种不可逆操作先警告。
- **给出口**：用户变卦时，弹窗或流程随时能退。

### 导航结构

单个流程之外，设计用户在整个 App 或站里的移动方式。导航烂，单个屏再好也没用——用户照样迷路。

- **主次分开**：主导航（标签栏、顶部导航）和辅助导航（设置、抽屉）明确区分。层级混了优先级就毁了。
- **限数量**：底部导航或标签栏最多五个。再多触发选择悖论。剩下的收进"更多"。
- **导航跨页面位置固定**：页面之间位置或内容一变，用户丢方向感。一致是导航可信的原因。
- **按屏尺寸换形式**：移动端底部导航或汉堡菜单；桌面侧边栏或顶部导航。同一个 App 可以按视口切换导航形式。

### 返回行为与状态保留

- "返回"要恢复之前的状态——滚动位置、筛选、输了一半的文字。返回全重置，等于擦掉用户的工作。
- 别无故清空导航栈。用户被突然送回首页会懵。
- 关键屏支持深链接（分享和通知进入需要）。

### 弹窗 vs 导航

弹窗打断流程，不代替导航。主流程（商品列表 → 详情 → 购物车）走弹窗，用户空间模型就破了。弹窗留给"临时岔路"——确认框、快速输入、设置微调。

## 降交互成本

用户每个动作都有点摩擦（交互成本）。同一目标，**摩擦小的设计赢**。

低摩擦的动作也靠"一直低摩擦"产生价值——没强理由别改它的行为。纵向滚动是用户最自然的动作，几乎无意识。scroll-jacking（劫持滚动的惯常行为做吸附或动画）把低摩擦动作变成不可预测的高摩擦。悬停同理：悬停触发大弹窗或页面跳转，悬停的随意感就没了。**低摩擦动作上别违背用户预期。**

摩擦主要由三个因素定：
- **付出**：需要的体力和脑力。
- **不可预测**：结果多难预期。
- **结果分量**：动作多难撤销、后果多大。

从低到高粗排：

**摩擦 1（被动——几乎无意识）**
- **看 / 读**：被动。不决策、不操作。
- **纵向滚动**：最习惯的主动动作。手指或滚轮连续一划。结果完全可预测（看到下面的东西）。无失败模式；随时可逆。
- **悬停**：鼠标移过去而已。无承诺；光标移开就回来。

**摩擦 2（结果可预测的轻动作）**
- **横向滚动**：没纵向习惯，但结果可预测（横向有更多内容）。轮播和画廊里摩擦依然低——不过藏起来的内容可能被忽略。
- **简单点击 / 轻触（点赞、复选框）**：一下，结果明确，常可逆。

**摩擦 3（结果带不确定性）**
- **页内切换（标签、手风琴、开关）**：要点一下，内容不完全可预测。没换页，但"里面是啥"不确定。
- **页内按钮点击**：带着决策。"该按吗？""按了会怎样？"进来了。
- **下拉 / 选择**：选项藏着；打开再选。选项多，搜索负担加上来。

**摩擦 4（要付出）**
- **文字输入**：切键盘、回忆正确的值、有打错风险。一个字段已经烦；多个字段直接推高流失。
- **触发页面跳转的点击**：加载时间、上下文丢失、渲染失败风险。目的地和预期不符，摩擦叠加。
- **表单提交**：文字输入的负担乘以字段数。校验报错要求返工，和放弃强相关。

**摩擦 5（心理门槛高）**
- **注册 / 登录**：交个人信息、设或回忆密码。"值吗？"的门槛。
- **支付 / 购买**：钱动了。难逆。
- **不可逆操作（删除、发送、发布）**：要确认；错了 blast radius（波及面）大。

设计含义：

- **滚动够就别让人点**：信息纵向铺一页，别用"下一步"按钮切碎。一页可滚常胜过多步分页。
- **减页面跳转**：能不能是标签、弹窗或行内展开？跳转必要时，加载尽量短。
- **减输入**：能选就别让输。自动补全、默认值、记住的值。
- **分阶段要承诺**：别一上来就要注册。先让用户体验产品，看到价值再要。
- **重动作配定心丸**：支付配"随时可取消"，删除配"30 天可撤销"。加信息稀释承诺的分量。

## 可访问性原则

可访问性不是对少数用户的客气——它是抬升所有人体验的设计原则。对比度（[color.md](color.md)）、聚焦环（[components.md](components.md)）、减弱动效（[motion.md](motion.md)）各有归属；跨领域的原则在这儿。

- **别只靠颜色传达**：报错是红 + 图标 + 文字。成功是绿 + 对勾。色盲用户只靠颜色分不出状态。
- **尊重标题层级**：h1 → h2 → h3 按序，别跳级。读屏软件用标题树画结构。视觉大小归 CSS 管。
- **键盘 Tab 顺序和视觉顺序一致**：左上到右下，跟着眼睛走。DOM 顺序和视觉顺序错位，键盘用户迷路。
- **纯图标按钮加标签**：图标视觉上再清楚，读屏软件只看到"按钮"。用 `aria-label` 或替代文字说清按钮干嘛。
- **文字放大不碎**：用户在系统设置里放大文字，布局不能碎。用换行或滚动扛，别裁剪或重叠。

## 不要做

- **一次展示所有信息**——认知负荷飙升。渐进披露。
- **跳过反馈**——"不知道发生了什么"是最糟的用户状态。
- **自创非标准 UI 模式**——守用户在别处学到的。自定义控件是学习税。
- **跳过空态 / 报错态设计**——"No data"/"出错了"没做完。指引下一步。
- **不可逆操作不确认**——删除、发送、发布先警告。
- **拒绝砍步数**——每个多余步骤都是流失点。
- **弹窗里套弹窗**——流程打断叠 buff，是最糟的 UX。
- **主流程走弹窗**——弹窗是临时岔路。商品列表 → 详情 → 购物车走弹窗，空间理解破。
- **每页导航乱变**——导航跨页保持一致。不然用户丢方向感。
- **返回清空状态**——恢复滚动位置、筛选、输了一半的输入。
- **只靠颜色传达**——色盲用户分不出。配图标或文字。
- **跳标题层级**——h1 → h3 的跳跃打断读屏软件的结构。

---

## 检查什么

- **新手不懵？** 从没见过这个屏的用户三秒内知道干嘛。
- **状态全覆盖？** 空态、加载、报错、成功、局部——都设计了。
- **100ms 内反馈？** 每次交互 100ms 内有视觉回应。
- **流程清楚？** 到目标的步数最少，"下一步干嘛"永远明显。
- **交互成本合理？** 同一目标有没有更低摩擦的动作？
- **守惯例？** 有没有打破用户在别处学到的模式？
- **好撤销？** 犯错能轻松回来吗？
- **导航一致？** 跨页位置结构一样。"返回"恢复之前状态。
- **可访问？** 不只靠颜色；标题顺序对；键盘顺序和视觉一致。
