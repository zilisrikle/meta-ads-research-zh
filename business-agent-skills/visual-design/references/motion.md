# 动效与动画指南

动态设计里的动画原则。动画不是装饰——是有目的的表达工具。每个运动都要回答「它为什么动？」

---

## 动画的两个目的

每个动画归结为两种角色之一。至少服务其中一个；哪个都不服务就别做。「有点动感挺好」不是理由。

### 1. 反馈——让状态变化可见

用动画让状态变化看得见，让用户直觉地理解刚才发生了什么：

- **状态变化可视化**：按钮按下、表单提交、数据加载、成功/错误态。即时响应让用户安心。
- **空间关系表达**：元素从哪来、到哪去。弹窗从底部滑入，直觉读作「它藏在屏幕下面」。
- **过渡平滑**：显示/隐藏、页面切换、标签切换——把生硬的状态切换柔化成自然流动。

没有反馈，用户会丢「刚才发生了什么」「现在这个状态是怎么来的」。按了按钮没反应，开始怀疑「到底按上了吗」。保存数据没可见变化，怀疑到底存没存。反馈动画消解这种怀疑。

反馈动画必须**短、轻、永远不挡交互**。让用户等的动画是帮倒忙。组件交互状态（hover、active、focus 等）的设计见 [components.md](components.md)。

### 2. 注意力——引导视线、激发兴趣

把焦点拉到特定元素，牵引用户的目光和好奇：

- **视觉冲击**：动态 hero 入场、滚动联动效果、视差。强第一印象的拉力。
- **丰富表达**：复杂动画效果、视频、3D、SVG 动画、粒子。用运动具象化品牌的世界。
- **工艺细节**：细腻的图标动画、讲究的加载指示、巧妙的 hover 效果。品质藏在小处。

注意力动画比反馈**更精巧、更复杂、更有表现力**。但滥用会变成噪声——集中在高冲击的时刻。

## 动画策略

不要把动画撒得到处都是。分层、有意地布：

### Hero 时刻

一个招牌动画。集中在冲击力最重要的地方——页面加载、hero 区、关键交互。一个做好的 hero 动画胜过十个散落的微交互。

### 反馈层

对用户操作的回应。按钮 hover/点击、表单校验、状态变化可视化。不是每个交互都要——集中在「沉默会显得坏了」的地方。

### 过渡层

状态之间移动的平滑。显示/隐藏、页面切换、弹窗开合、手风琴展开。把生硬切换变成自然流动。

### 愉悦层

功能上不必要、但丰富体验的运动。完成庆祝、空态的漂浮插画、奖励探索的彩蛋。省着用——过头就从讨喜变油腻。

## 时长与缓动

### 时长指南

合适的长度看目的：

- **100–150ms**：即时反馈（按钮按下、开关、hover 变色）
- **200–300ms**：状态切换（菜单开合、标签切换、tooltip）
- **300–500ms**：版式变化（手风琴、弹窗、抽屉）
- **500–800ms**：入场动画（页面加载、hero 元素出现）

**离场要比入场快**——大约是入场时长的 75%。用户不关心正在离开的东西，赶紧送走。

### 缓动

避开 CSS 默认的 `ease` 和 `linear`。用自然减速的缓动。物理世界里东西不会瞬间停住——会慢下来：

- **ease-out 系**：大多数动画适用。带着惯量出发，自然落定。
- **ease-in-out**：适合横穿屏幕的元素。加速再减速。
- **linear**：避开。感觉机械、不自然。只限进度条等少数场景。

bounce 和 elastic 缓动跳过。显旧，还把注意力吸到动画本身。

## 具体动画模式

### 入场动画

- **页面加载**：元素错峰（100–150ms 延迟）。淡入 + 位移组合。
- **滚动触发**：进入视口时淡入。用 Intersection Observer。
- **弹窗 / 抽屉**：位移 + 淡入 + 背景遮罩。

### 微交互

- **按钮**：hover 轻微放大（1.02–1.05）或变色。点击快速缩小（0.95 → 1）。按钮变体和尺寸见 [components.md](components.md)。
- **表单**：聚焦时边框色过渡。错误时抖动，成功时对勾。表单校验设计见 [components.md](components.md)。
- **开关 / 复选框**：平滑的滑动和颜色过渡。

### 状态过渡

- **显示 / 隐藏**：淡入 + 位移。避免瞬间切换。
- **展开 / 折叠**：高度过渡 + 图标旋转。
- **加载**：骨架屏 shimmer、进度条。

### 导航

- **页面过渡**：交叉淡入或共享元素过渡。
- **标签切换**：活跃指示器滑动 + 内容淡入。
- **滚动效果**：视差、吸顶导航状态变化。

## 性能

卡顿的动画是帮倒忙。为 60fps 设计：

- **只动 `transform` 和 `opacity`**：这两个有 GPU 加速。动 `width`、`height`、`top`、`left` 触发重排——避开。
- **`will-change` 省着用**：只在真需要的地方。滥用浪费内存。
- **隔离重型动画**：持续跑的 CPU 重型动画放在小组件里，别触发父级重渲染。

---

## 可访问性

每个动画必须尊重 `prefers-reduced-motion`。对动效敏感的用户，过度动画会引发头痛或恶心。

- 开启减弱动效时，禁用或大幅简化动画。
- 确保关键信息不靠动画传达。
- 自动播放的动画（循环、滚动联动）格外小心。

---

## 不要

- **无目的动画**——每个动画都要有「反馈」或「注意力」的理由。
- **什么都动**——动画疲劳耗尽界面。集中在关键时刻。
- **动画期间挡交互**——反馈动画永远不能碍事。
- **反馈超过 500ms**——感觉迟缓。反馈要短。
- **用 bounce / elastic 缓动**——显旧，还让动画本身成主角。
- **无视 `prefers-reduced-motion`**——可访问性违规。
- **动版式属性**——用 `transform` 和 `opacity` 代替。

---

## 检查什么

- **60fps 顺滑吗？** 目标设备上不卡。
- **感觉自然吗？** 缓动读作有机自然，不机械。
- **时长合适吗？** 不太快（生硬），不太慢（迟缓）。
- **减弱动效成立吗？** `prefers-reduced-motion` 下动画正确禁用。
- **不挡交互吗？** 动画播放时用户还能操作 UI。
- **加分吗？** 去掉这个动画体验会变差吗？不会就删。
